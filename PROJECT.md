- **LLM providers (P1-T02/T03):** one OpenAI-compatible adapter covering eight presets, plus native Anthropic and Google. The native pair **discovers nothing** — no browser-reachable listing endpoint exists, so each ships a curated catalog and is therefore the *enriched* path, where `capabilities` is always known. Anthropic is the only one that can report `promptCaching`. **All of it is now live-verified (2026-09-12)**: nine endpoints — Ollama local and cloud, LM Studio, NVIDIA, DeepSeek, QwenCloud on both the OpenAI-compatible and the native-Anthropic path, Anthropic, Gemini — stream text, return a tool call as its own `tool-call` chunk, keep reasoning out of `text-delta` and end with `finish`. Anthropic's 1M/1M/200K context lengths are confirmed against `max_input_tokens`, and **Gemini's `contextLength` is no longer `null`**: `GET /v1beta/models` reports `inputTokenLimit` 1048576, so the catalog carries that. **The live run found a product problem, not an adapter one:** a thinking model can spend its whole output budget reasoning and emit no text at all — `temperature: 0` did it on Ollama, and LM Studio did it at `temperature: null` in 89.7 s. P1-T10 must never send `temperature: 0` to a `thinking: true` model, and must treat "finished with `length` and no text" as a failure the UI shows.
- **Sentence chunker (P1-T04):** `packages/core/chunker` splits a token stream into TTS-sized chunks and lifts `[emote:x]`/`[gesture:x]` out into tags. **Nothing calls it yet** — P1-T05 (TTS) and P1-T11 (transcript) are what consume it. Two things it inherits forward: `maxChars: 200` is **measured and unchanged (2026-09-12)**: on a GPU Kokoro server synthesis costs ~1.29 ms per character and runs ~44x faster than speech, so chunk length cannot starve playback, and the cap never touches the opening — 120, 200 and 320 give an identical first chunk. **No first-chunk cap is needed on this path**: a full opening sentence reaches first audio in 137 ms and a 245 ms budget buys 178 characters. An earlier reading said the opposite (15.3 ms/char, 1525 ms) and was measuring a server that had silently fallen back to CPU torch — the browser path still wants its own reading in P1-T08; and **ADR-23 defers the tag protocol to P1-T12**, which must close that ADR explicitly rather than inherit it. Tag offsets index the *spoken* text, because P2 schedules against TTS word timestamps.
- **TTS providers (P1-T05):** three behind one interface — `KokoroBrowserTTSProvider` (a worker in `packages/ml-web`, WebGPU, 28 built-in voices, 24 kHz), `OpenAICompatibleTTSProvider` (`POST /audio/speech`, verified against OpenAI's schema and Kokoro-FastAPI's source), and `FakeTTSProvider`. **Neither real provider returns word timings**, so P2's viseme scheduling plans on wawa-lipsync analysis — the branch `capabilities.ts` anticipated in writing. Kokoro reports `emotionHints: false` because its surface has no emotion parameter at all; the server adapter can carry one through OpenAI's `instructions`, off by default. **ADR-24: audio crosses as Float32 PCM and the adapter parses `wav` itself**, so no test needs a DOM — and nothing streams within a sentence, because P1-T04 already made the sentence the unit of latency. **The server half is verified live (2026-09-12)** against a real Kokoro-FastAPI: 72 voices in the object shape — including language families kokoro-js has never heard of — 24 kHz WAV decoded by `wav.ts`, **real-time factor 0.06 on the GPU** (0.25–0.41 before the CPU-torch fix), and a bad voice returning the server's own words. **`speed` is honoured but only usable to ~1.25**: above it the server hits the requested duration ratio while the phonemes degrade, so duration cannot detect the fault and a settings UI must not offer the API's full 0.25–4. Re-encoding the decoded samples plays back correctly, so the whole chain is proven bar the play-out path. **Nothing plays it in the app yet**: that is P1-T08. Kokoro's `fp32` default is 325.5 MB against `q8`'s **92.4 MB** (the old 86 MB figure named `model_q8f16.onnx`, a file `dtype: 'q8'` never fetches — transformers.js maps `q8` to the `_quantized` suffix). **They are now compared and indistinguishable**, measured and by ear, but **`fp32` stays the default**: that ran on onnxruntime-node and this provider runs WebGPU, where ADR-20 records a q8 graph returning fluent nonsense with no error. **P1-T08 owns the browser check** — and must clamp, because Kokoro's output is not bounded to [−1, 1] (peak 1.043).
- **STT providers (P1-T06):** four behind one interface — `MoonshineBrowserSTTProvider` and `WhisperBrowserSTTProvider` (a shared worker in `packages/ml-web/src/asr`), `OpenAICompatibleSTTProvider` (`POST /audio/transcriptions`, multipart, verified against the official `openai` client 2.53.0) and `FakeSTTProvider`. **Neither browser model streams** — both consume a whole utterance — so the fake is the only one that produces partials. **Quantised precisions are refused on WebGPU** in both the provider constructor and the worker, because of ADR-20's silent-nonsense finding. Four facts were established by reading transformers.js's source or running it, and each changed the code: the pipeline **does not resample** (48 kHz read as 16 kHz gave Moonshine nothing and Whisper a fluent invented sentence, with no error); `_call_moonshine` returns text only, so Moonshine can never report word timings; **the plain `onnx-community/whisper-*` exports throw on any request for word timings**, so the catalog names the `_timestamped` variants, which cost 23 KB less; and a `max_new_tokens` floor that looked obviously right made Moonshine answer "Yes, yes, yes." and was removed — **but the conclusion drawn from it, that the library budget is safe, was wrong and P1-T07 corrected it** (below). **Verified end to end in node**: Kokoro speaks, both models transcribe, **0% word error rate** on both sentences — Moonshine at 118-139 ms, Whisper at 754-817 ms with working word times. The done-when (**live transcription in the transcript panel**) is not met and is not meetable yet: no microphone until P1-T07, no panel until P1-T11. `docs/briefs/P1-T06.md`.
- **Turn detection (P1-T07, 2026-09-13):** `TurnDetector` in `packages/core/src/turn` is the endpointing logic with no model in it, tested on scripted probabilities; Silero and Smart Turn are two thin workers in `packages/ml-web/src/turn` over model modules the live check shares; `SmartTurnJudge`, `BrowserSileroVad` and `speculativeTranscription` are in `packages/providers/src/turn`. **ADR-21's overlap is built**: one synchronous step hands the same buffer to the judge and to recognition, and **recognition is cancelled only when speech resumes** — never on a low probability, since the hangover then closes the turn on the same words. `speculativeTranscription` exists because `transcribe` is a lazy generator and the obvious wiring silently starts recognition at turn end instead. **`pnpm live:turn` replaces the recorded fixtures**: Kokoro speaks labelled utterances and the shipped code endpoints them — **complete sentences end 168 ms median, 220 ms worst after the label** at Spike D's WebGPU answer latency, 0 of 12 cut off, **0% WER on every kept window**. That reproduces 168 ms; it does not re-measure WebGPU, which node lacks. **Three findings changed code.** Silero's reference input is 576 samples (64 of context), not the 512 the spikes fed — context detects onset up to 64 ms sooner and stops early speech-ends in noise. **Smart Turn ends sentences at inner pauses whose prefix sounds finished**, and more so the faster it answers: 4 of 6 cut off at WebGPU latency, so **ADR-25 (proposed)** makes a model end retractable until `hangoverMs` after speech stopped — `turn-resumed`, same turn, stale recognition cancelled; consumers must not treat a `model` end as final before `confirmedAt`, and the protocol has no retraction event yet. And **transformers.js's Moonshine budget floors the seconds**, so 1–2 s of speech got six tokens and lost its last words (9 of 15 windows); `asr.worker.ts` now sends `ceil(seconds × 6)`. Kokoro's "incomplete" fragments are spoken as finished sentences, so this check **cannot** measure false fires on held pauses — Spike D's 0 of 51 stands on its own. `docs/briefs/P1-T07.md`.
- **Voice pipeline (Spike A, 2026-09-08):** 947 ms end of speech to first audio on WebGPU/fp32; 435 ms excluding the VAD hangover, against ADR-20's 500 ms pipeline budget. WebGPU is required — wasm synthesis is 3779 ms. q8 recognition is broken on WebGPU. Details in `docs/spikes/A-voice-loop.md`.
- **Turn detection (Spike D, 2026-09-08):** **Go.** Smart Turn v3 on fp32/WebGPU with a 100 ms candidate and a 0.7 threshold answers in **168 ms** against the 512 ms hangover it replaces, and interrupted 0 of 51 held pauses across the five runs after the first. int8 will not load on WebGPU at all (loudly) and is a no-GPU fallback. First audio becomes ~593 ms sequential, ~553 ms once recognition overlaps turn detection - which ADR-21 makes P1's job, against an unchanged 500 ms budget. `docs/spikes/D-smart-turn.md`.
- **Avatar (Spike B, done 2026-09-09):** **Go.** A full-body VRM 1.0 with MToon, spring bones and constraints runs at **120.5 fps median at 1916×1076** on an RTX 5060 Ti — the budgeted 1080p — and the worst frame of the run (15.0 ms) still fits inside 60 fps. Quadrupling the pixels moved neither the median nor the 5th percentile, so the scene is display-bound, not fill-rate bound. Lip sync reads as speech. **wawa-lipsync emits fifteen Oculus visemes, not VRM's five**; the mapping is in `packages/avatar` with tests. `docs/spikes/B-vrm-lipsync.md`.
- **Memory store (Spike C, done 2026-09-09):** **Go.** MariaDB 11.8.8 stores `VECTOR(768)` bit-exactly and answers a top-8 at **100k rows in 4.90 ms median, 8.47 ms p95** on the LAN, `EXPLAIN` naming the index at 10k and 100k. Against the 100 ms per-turn budget that is ~12x headroom locally; over the 39.8 ms tunnel one statement is 44 ms, two 86 ms, three 128 ms, so **ADR-17's one-call rule is confirmed with arithmetic**. `mhnsw_ef_search` is session-settable and at 320 the p95 is still 12 ms, so recall is an affordable dial — but recall itself is **not measurable from a random fixture** and belongs to P4. `docs/spikes/C-mariadb-vector.md`.
- **Server tuning is a shipping requirement, not a preference:** the stock `mhnsw_max_cache_size` is **16 MB** against 307 MB of vectors at 100k rows, which cost a **5x** query slowdown and made 100k unreachable. It is `GLOBAL`-only, so no application user can set it and the product cannot detect or fix it from inside. Whatever ships must document it.
- **Linux handoff (2026-09-09):** the repo is portable — `.gitattributes` forces `eol=lf`, no script is platform-specific, and **no LFS payload is actually committed**, so a plain `git pull && pnpm install` is enough. Spike E's risk is the webview, not the toolchain.
- **Desktop shell (Spike E, Linux leg 2026-09-09):** **No-go for Tauri on Linux.** `navigator.gpu` is **undefined** in WebKitGTK 2.52.5 — the JS bindings are not in the build, and the library ships the string `WebGPU platform is unsupported.` Spikes A, D and B all need WebGPU, so **Linux ships as companion + Chrome**, which is ADR-07's own fallback clause rather than a new decision (ADR-07 amended). The shell also **will not start on GNOME Wayland** with the NVIDIA driver — explicit-sync protocol error on first commit — and WebKitGTK's own MiniBrowser dies identically, so that one is the port, not Tauri. `GDK_BACKEND=x11` works. `docs/spikes/E-tauri.md`.
- **Desktop shell (Spike E, Windows leg 2026-09-11):** **Go.** WebView2 **152.0.4191.66** gives a real WebGPU adapter (`nvidia / blackwell` — the probe rejects software rasterisers, so it means it), a live microphone, AudioWorklet, WebGL 2 on the discrete card, and a tray. ADR-07's Windows-first path is confirmed as written. **The microphone is the sharpest contrast with Linux**: same wry, `NotAllowedError` there and a stream here, so wry's permission handling is platform-specific — P8-T02 inherits that. `SharedArrayBuffer` is NO in all four containers measured, which locates it in the Vite dev server (no COOP/COEP) and means **Spike A's 3779 ms wasm figure was single-threaded** — now a P1 question, since wasm is the shipping path on Linux. **Windows notifications need an installed app**: the Rust call returns `Ok` and draws nothing from a dev binary, because Windows routes toasts by AppUserModelID and only a Start Menu shortcut supplies one — 82 apps registered on that box, zero for us. **P8-T01's NSIS installer is the fix and P8-T05 cannot be tested from `cargo run`.** The icons are now generated from `site/img/presence_512x512.png` rather than Tauri's scaffold logo, so no third-party asset is vendored and the `NOTICE` obligation is gone.
- **The Linux fallback is not free, and that is Phase 8's problem to inherit:** Chrome 153 on that box gave **no WebGPU adapter as launched** — its GPU sandbox could not read the Vulkan ICDs, though `vulkaninfo` sees the RTX 5060 Ti fine. `--disable-gpu-sandbox` gives `nvidia / blackwell`; `--enable-unsafe-webgpu` gives **`google / swiftshader`**, software, which passes a naive check and would silently miss every budget. One box, one distro, one very new driver — enough to decide Tauri-vs-Chrome, not enough to characterise Chrome on Linux.
- **The desktop crate is not gated, on purpose:** `apps/desktop/src-tauri` is its own cargo workspace and `pnpm gate` does not touch it. `pnpm gate:desktop` checks it on demand. Gating it would put tauri/wry/tao/webkit2gtk on every gate on every machine and need `libwebkit2gtk-4.1-dev` on CI's ubuntu runner, for a crate Phase 8 owns. **P8 should reverse this.**
- **Live:** `latentpresence.com` serves the site, docs and feedback form; a submission was confirmed end to end on 2026-09-08. Deploy is `git pull` + `pnpm build` on the server (ADR-16). `app.latentpresence.com` has no build behind it yet.

## Spike harness

Three dev-only routes in `apps/web`, all dropped from production builds by the guard in `vite.config.ts` (it fails the build if any reaches a chunk). `/spike/voice` is Spike A: consent, Silero + Moonshine + Kokoro, per-turn timing. `/spike/avatar` is Spike B: a VRM in react-three-fiber with lip sync and a frame-rate model. `/spike/shell` is Spike E: the webview capability probe, which prints a copyable markdown table and hands it to the Tauri host if there is one. **`/spike/turn` (Spike D) was deleted by P1-T07 (2026-09-13)** with its guard entry, as its trigger said; the candidate path it had added to Spike A's VAD worker went too. **Spike A's trigger was "when P1-T06 and P1-T07 land", and it is kept one task longer, deliberately**: it is the only page in the repo that plays synthesised audio in a browser on WebGPU, and P1-T08's done-whens (Kokoro `q8` on WebGPU, clamping) need exactly that until P1-T08 builds the real queue. **It goes when P1-T08 closes.** B's guard entries come out at **P2-T01**, deliberately, because the avatar stops being dev-only there. **E was to go when P0-T08 closed, and is kept instead**: Phase 8 inherits two claims this spike deliberately left unverified — that an installed Windows build actually draws a toast, and what Chrome on Linux does for WebGPU without `--disable-gpu-sandbox` — and the probe is the instrument for both. It is dev-only, guarded and tested, so it costs a build assertion and nothing else. **It goes when P8-T01 closes.**

The boot screen carries a **dev-only index of those routes**. It is not decoration: a Tauri window has no address bar, so without it the shell opens on `/` and no spike route is reachable from inside it at all.
