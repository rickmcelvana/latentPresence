## Last three sessions

- 2026-09-23 claude — **P3-T01: the affect core, bounded by its shape rather than by a clamp.** The protocol already had every type, so the task was dynamics: relax to a baseline, push by a saturating fraction toward the edge, fixed steps with inputs on boundaries. Property tests with a seeded RNG did the proving and found the one real cost (ISO strings per step made a day's catch-up 13 s for the suite); mutations confirmed each property can fail. **Method lesson: when a done-when says "bounded", make the bound a property of the update rule and let the tests attack it with nonsense inputs — a clamp would have passed them and hidden a runaway.**

- 2026-09-24 claude — **P3-T03: her mood in her voice and her words.** The protocol already had `EmotionHint` and `TtsRequest.hint`, but the default voice ignores hints entirely, so the audible half had to be prosody we own — pace and the pause after each sentence — and the wording half a note that names the feeling in words and says how much to say. Both models followed it without ever announcing the mood; the live run also caught a third tag spelling that would have been spoken. **Method lesson: when a capability flag says the backend drops your signal, find the part of the output you control and measure it on the rendered audio, not the parameters.**

- 2026-09-24 claude — **P3-T09: her mood in the call, and the baseline that was not an identity.** Wiring the engine into `/chat` was mostly plumbing, but two facts only showed up by reading what already existed: `affectToBody` is neutral at energy 0.5 and engagement ≤ 0, while Alice rests at 0.6 and 0.3 — so the body is driven relative to her own baseline — and a typed answer shown as text had never put its sentences on the bus, so its tags would have been felt by nothing. **Method lesson: when a done-when says "at baseline it looks as today", test that literally — same frames with and without the new input — rather than trusting that a neutral input is a no-op.**

## Spike harness

Five dev-only routes in `apps/web` — **`/dev/avatar` (P2-T01) is the avatar's debug panel: expressions, mouth, gaze, clips, life, lip sync, the stage and a frame-rate reading** — all dropped from production builds by the guard in `vite.config.ts` (it fails the build if any reaches a chunk). **`/dev/voice` (P1-T08)** is the promoted voice pipeline with a scripted model, a simulated speaker, a click check and a voice check — it **replaced Spike A's `/spike/voice`**, deleted with its workers, `audio.ts` and metrics when P1-T08 closed, as its trigger said. **Its removal trigger has now fired and the page stays anyway, deliberately:** P1-T15 put the pipeline behind a real route on 2026-09-22, and the guard's model needles came out with it, but the *page* is the only instrument for the things a person measuring cannot do from `/chat` — a speaker with no microphone, a barge-in on a timer, the click analysis of the rendered output, and Kokoro against node's renderings. It goes when something else carries those four. **`/dev/e2e` (P1-T14) joins it** — a fourth dev-only route, driven by Playwright rather than a person, with the model, the voice and recognition faked so CI needs no WebGPU. `/spike/avatar` is Spike B: a VRM in react-three-fiber with lip sync and a frame-rate model. `/spike/shell` is Spike E: the webview capability probe, which prints a copyable markdown table and hands it to the Tauri host if there is one. **`/spike/turn` (Spike D) was deleted by P1-T07 (2026-09-13).** B's guard entries **came out at P2-T06**, when `/chat` began mounting the renderer: `three-vrm` in a production chunk is now expected, so the guard names `@react-three/fiber` (only `/spike/avatar` uses it) and a string only `/dev/avatar` carries, both mutation-checked. `/dev/avatar` (P2-T01) is the renderer's debug panel; `/spike/avatar` stays as R-1's frame-rate instrument. **E was to go when P0-T08 closed, and is kept instead**: Phase 8 inherits two claims this spike deliberately left unverified — that an installed Windows build actually draws a toast, and what Chrome on Linux does for WebGPU without `--disable-gpu-sandbox` — and the probe is the instrument for both. It is dev-only, guarded and tested, so it costs a build assertion and nothing else. **It goes when P8-T01 closes.**

The boot screen carries a **dev-only index of those routes**. It is not decoration: a Tauri window has no address bar, so without it the shell opens on `/` and no spike route is reachable from inside it at all.
