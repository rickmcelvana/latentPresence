# P0-T02 Protocol package — brief

Owner: main (architect-direct). Depends: P0-T01. ADRs: 03, 04, 05, 06, 11, 12, 14.
Interfaces here change only in architect-owned tasks with an ADR note (CLAUDE.md).

## Goal

The shared vocabulary every other package compiles against: what a provider is, what the character
feels, what happens in a conversation, what memory holds, and what the companion answers. Nothing in
this package does work — no I/O, no DOM, no audio. It is types, schemas and the route table.

## The zod / TypeScript line

**zod for anything that crosses a boundary**: persisted rows, HTTP and WS bodies, saved settings,
LLM-emitted structures, anything read back from a file. **Plain TypeScript for in-process values**:
audio buffers, async iterables, renderer handles, callbacks. A `Float32Array` of PCM never needs
parsing, and a schema for it would be theatre. The README states this rule so later tasks follow it.

Zod 4 surface facts (checked live, `docs/SURFACE.md` 2026-09-08): `z.partialRecord` for partial maps
over an enum, `z.record(enum, v)` demands every key; `z.iso.datetime()`; `z.lazy` with an explicit
`z.ZodType<T>` annotation for recursion; unknown keys are stripped unless `z.strictObject`.

## Contents

Split over two commits, both under this task id, so each diff stays reviewable.

Part 1 — the data the app moves around
- `common.ts` — ids, ISO timestamps, `UnitInterval`, `SignedUnit`, `JsonValue` (recursive)
- `affect.ts` — PAD mood, emotion vocabulary, `EmotionEvent`, `AffectState`, `UserAffect` with the
  per-channel estimates that fused into it, and the engine's outputs: expression weights, gaze
  policy, TTS emotion hint (ADR-12, RESEARCH §5)
- `conversation.ts` — `ToolCall`, `ToolResult`, `ConversationEvent` as a discriminated union over
  the P1-T01 state machine's traffic, including barge-in with the prefix actually spoken
- `schedule.ts` — `Schedule` with trigger, delivery mode, catch-up policy, status, `runOn` (ADR-14)

Part 2 — the ports
- `capabilities.ts` — one capability object per provider kind, plus `ProviderDescriptor` so the
  settings UI (P1-T10) can render a provider it has never heard of
- `providers/{llm,stt,tts,embedding,omni}.ts` — config and result schemas, and the TS interface
- `memory.ts` — episodes, bi-temporal facts, self-model blocks, plans, and `MemoryStore`, whose
  retrieval is **one batched call per turn** because the dev database is across a WAN (ADR-17)
- `avatar.ts` — `AvatarRenderer` and its capabilities (ADR-03)
- `companion.ts` — the route table for `/health`, `/db/*`, `/ingest/*`, `/mcp/*`, `/schedules/*`,
  each entry carrying method, path, request schema and response schema, plus the WS event union and
  one error envelope
- `README.md` — what each module holds, the zod/TS rule, and how to add to it

## Tests

One test file per module. "Round-trips a sample" is the floor, not the test: each schema gets a
valid sample that parses to the expected value **and** a specific invalid sample that must be
rejected at a named path. A schema loosened by accident has to fail one of these. Plus:
- every `ConversationEvent` variant is reachable through its discriminator
- the companion route table has no duplicate method+path and every entry has both schemas
- expression weights reject a name outside the vocabulary
