`--on-accent` is new against the reference and matters: teal is light enough that white text on a
filled button fails contrast, so `.btn-primary` takes `color: var(--on-accent)`.

Delete reference rules for sections this site does not have. A stylesheet carrying rules for a
`.pillar` that appears nowhere is the same defect as an element with no rule, pointing the other way.

## The landing page

Same shell as the reference: `.container`, `.nav` with wordmark and links, then the sections. Nav
links: Features (`#features`), How it works (`#how`), Docs (`docs/`), and a `.btn.btn-primary` to
`https://app.latentpresence.com` labelled "Open the app".

The wordmark carries the mark, which the reference does not have and this site does:

```html
<a class="wordmark" href="/"><img class="logo" src="img/mark.svg" width="28" height="28" alt=""> latentPresence</a>
```

so `.wordmark .logo` needs a rule: `display:block; flex-shrink:0; width:28px; height:28px`. Paths are
relative to each page, so `docs/` and `feedback/` use `../img/mark.svg`.

Copy to use, close to verbatim. It is drawn from `README.md` and `docs/RESEARCH.md`, so it is
already true; do not embellish it, and do not invent features, benchmarks or testimonials.

**Hero.** Eyebrow: "Open source · Bring your own models". Headline: "A conversational AI you talk to
face to face." Lead: "A full-body character lives in a small 3D set and joins you in a video call.
You speak or type, it listens, reacts, and answers in voice with matching expression and body
language." Buttons: "Open the app" (primary, `https://app.latentpresence.com`) and "Read the docs"
(secondary, `docs/`). Fine print under them: "Early development. Nothing here is finished yet."

**Story** (`#story`). Two or three short paragraphs: most assistants are a text box; a face that
listens and reacts changes what talking to one feels like; this one remembers you, helps you plan,
runs tasks you schedule, answers from your own documents, and can run your smart home through Home
Assistant.

**Features** (`#features`), a `.feature-grid` of `.feature-card`s, one each:
- **It has a face.** A full-body VRM character with lip sync, expressions and idle life, rendered in
  the browser with three.js.
- **It reads the room.** Voice, text and — only if you turn the camera on — your face feed one
  estimate of how you seem, and the character's mood answers it.
- **It remembers.** Episodes, facts with the dates they were true, plans, and a self-model it edits.
  In your MariaDB, your SQLite, or your browser.
- **It does things later.** "Every weekday at eight, summarise my notes folder." Visible in a panel,
  cancellable, and confirmed aloud when you create it.
- **It answers from your documents.** Your PDFs, notes and databases, with citations you can open.
- **It runs on your models.** Ollama, LM Studio, vLLM, llama.cpp, OpenRouter, NVIDIA, Anthropic,
  OpenAI, or models you download into your own browser.

**How it works** (`#how`), `.how-steps` of `.how-step`, four steps: pick your models → allow the mic
→ talk → it remembers. One sentence each.

**Privacy** (`#privacy`), a `.promise` block. This is the section that must not drift, so use these
lines: "No telemetry, ever. Nothing leaves your machine unless you point it somewhere." · "We ship no
models. Anything that runs in your browser is downloaded by you, after a screen showing its size,
licence and source." · "Your memory lives in your database, not ours." · "The camera is off until you
turn it on, and video never leaves the page."

**Footer.** Wordmark, links to Docs, Feedback, GitHub (`https://github.com/rickmcelvana/latentPresence`),
and the line "Apache-2.0. Part of the Latent suite."

## The feedback form

Markup follows the reference exactly, including the honeypot field, `role="status"` on the status
paragraph, and `noindex, follow` in the robots meta. Change the nav links to this site and the title
to "Report a bug / send feedback — latentPresence".

`feedback.js` is the reference handler with **one** change, and it is the change the whole task turns
on:

```js
  const payload = {
    // Which product this report is about. Must stay in step with `normalize_source`
    // in the feedback API; anything else lands as 'unknown' and is unactionable.
    source: 'presence',
    kind: form.kind.value,
    message: form.message.value,
    email: form.email.value || null,
    _hp: form._hp.value,
    user_agent: navigator.userAgent,
    screen_width: window.innerWidth,
    screen_height: window.innerHeight,
  };
```

Keep `_hp` in the payload even when empty: the API deserialises it as a bare string, so omitting it
fails the request before the handler runs (`docs/SURFACE.md`, 2026-09-08). Keep the `429` branch and
its wording — the API rate-limits five per IP per hour, and a user who trips it deserves to be told
that rather than "something went wrong". Success is `204`, so test `res.ok`, never `res.json()`.

## Deploy

`scripts/deploy.sh`, POSIX `sh`, `set -eu`. The repository is public, so **no hostname, user or path
is written into the script**. It reads them from the environment, sourcing `.env` if present, the
same way the companion reads `DATABASE_URL` (ADR-17):

```
DEPLOY_HOST      user@host for ssh/rsync
DEPLOY_SITE_PATH  server directory Caddy serves latentpresence.com from
DEPLOY_APP_PATH   server directory Caddy serves app.latentpresence.com from
```

Behaviour:
- Dry run is the **default**. `--live` (or `--no-dry-run`) is what actually writes. A deploy script
  whose safe mode needs a flag is a deploy script that eventually runs without one.
- Missing variables exit non-zero naming the variable, before touching the network.
- Refuses to sync `apps/web/dist` if it does not exist, telling the caller to run `pnpm build`.
  Syncing an absent directory with `--delete` empties the live site.
- `rsync -av --delete` per target, over ssh.
- Prints the two source→target pairs before running, in both modes.
- `chmod +x`.

## Tests

`site/style.test.ts`, run by the `site` vitest project, in the spirit of ADR-15 and of
`apps/web/src/theme.test.ts` — read that file first and follow its shape.

1. **Every class in the site's HTML has a rule in `site/css/style.css`.** This is what makes "renders
   with no unstyled element" checkable instead of a matter of opinion. Scan every `.html` under
   `site/`, extract `class="..."` values, compare against the classes the stylesheet defines.
2. **Every rule in the stylesheet is used by some page.** The reverse direction, because this
   stylesheet is copied from a site with sections we do not have, and dead rules are what get copied.
3. **The feedback payload names exactly the API's fields.** Parse `site/feedback/feedback.js`, and
   assert the payload object's keys are exactly `source, kind, message, email, _hp, user_agent,
   screen_width, screen_height`, and that `source` is the literal `'presence'`. The invariant: a
   renamed or dropped key means reports silently land as `unknown`, or fail to deserialise, and
   nothing else in the repo would notice.
4. **Every page links a stylesheet, a manifest and the favicons, and sets a description.** The
   invariant is the one that actually bites on a static site: a new page copied from another one with
   a relative path that does not resolve from its own directory. Check the referenced files exist on
   disk relative to the page.
5. **`sitemap.xml` lists every page that is not `noindex`, and lists nothing that is.** Feedback is
   `noindex, follow`, so it must be absent; index and docs must be present.

Each test states the invariant it protects in a comment, as in the rest of the repo. No test may
assert on wording or on colours — copy changes, and the tokens are checked elsewhere.
