## Reference implementation

Transcribe `packages/providers/src/llm/openai-compatible.ts` — same class shape, same `stream()` body, same reuse of `toAiMessages` / `toAiTools` / `mapStreamPart` and the same `AbortController` cancellation. The only differences are the provider factory, the id, and model discovery:

**`anthropic.ts`** — provider factory:

```ts
import { createAnthropic } from '@ai-sdk/anthropic';
// settings: { apiKey?, baseURL?, headers?, fetch? }  (apiKey sent as x-api-key; baseURL default https://api.anthropic.com/v1)
const provider = createAnthropic(settings);
const model = provider(modelId); // e.g. 'claude-sonnet-4-5'
```

**`google.ts`** — provider factory:

```ts
import { createGoogleGenerativeAI } from '@ai-sdk/google';
// settings: { apiKey?, baseURL?, headers?, fetch? }
const provider = createGoogleGenerativeAI(settings);
const model = provider(modelId); // e.g. 'gemini-2.5-flash'
```

### Model discovery: a curated catalog

Native providers have **no `/v1/models`-style discovery endpoint**. `listModels()` returns a small curated `LlmModel[]` catalog (so the picker has entries and the capability flags are reported), never a live call. Catalog shape per model (protocol `LlmModel`): `id`, `label` (same as id), `capabilities`, `embeddingOnly: false`.

Use `known` capabilities (all `capabilities` non-null — this is an enriched path):

| Provider | Model ids (`id`) | `capabilities.thinking` | `capabilities.promptCaching` | `contextLength` |
|---|---|---|---|---|
| Anthropic | `claude-sonnet-4-5`, `claude-opus-4-1`, `claude-haiku-4-5` | true | **true** | 200000 |
| Google | `gemini-2.5-pro`, `gemini-2.5-flash`, `gemini-2.5-flash-lite` | true | true | 1048576 |

For both every model also: `streaming: true`, `toolCalls: true`, `structuredOutput: true`, `vision: true`. **These catalog ids must be the current model ids accepted by the installed `@ai-sdk/anthropic@4` / `@ai-sdk/google@4` provider** — confirm against the installed package docs/`docs/05-anthropic.mdx` and the google provider docs, and against **live streaming with a real key** in the manual verify. Do not invent an id; if a listed id is wrong, fix it to the documented one.

**Provider config** (both): `{ id: 'anthropic' | 'google', apiKey?, fetch? }`. Constructor signature mirrors `OpenAICompatibleLLMProvider` (`id` + config), including the `now` timestamp parameter used for `tool-call` chunks.

**`stream()`**: identical body to `openai-compatible.ts` — build `streamText({ model, messages: toAiMessages(request.messages), tools: toAiTools(request.tools), abortSignal, temperature?, maxOutputTokens? })`, iterate `result.fullStream`, `mapStreamPart(part, now)`, skip `null`. Cancellation via the caller's `signal` aborts the `AbortController`. Reuse `buildProvider`-style settings assembly (only set `apiKey`/`fetch` when present).

## Tests, each with the invariant it protects

Because streaming needs a real key (producer-owned manual test), the unit tests cover the deterministic surface only:

- `anthropic listModels returns the curated catalog with known capabilities` — would fail if a native adapter hid its capability flags or reported `embeddingOnly: true`; guards that the picker can present and hide models from the catalog.
- `anthropic reports promptCaching true on every catalog model` — would fail if the task's headline flag were missing/misreported.
- `google listModels returns the curated catalog, all capabilities non-null` — would fail if the native path ever returned `capabilities: null` (it is enriched, unlike `/v1/models`).
- `anthropic implements LLMProvider (id + listModels + stream)` — would fail if a provider stopped satisfying the protocol contract.
- `stream replays no chunks with no tools (mapping unchanged)` — optional; if included, keep it to the pure `mapStreamPart` layer, never a real HTTP call.
- `index re-exports anthropic and google` — would fail if the entry point did not expose the new providers.

Mirror `openai-compatible`'s structure; a shared `FakeLLMProvider` already exists and is reused for any stream-shape test.
