# P1-T06 — STT providers

- **lane:** main (architect-direct)
- **status:** landed
- **gate:** green, 486 TypeScript / 17 Rust
- **date:** 2026-09-12

This is a record, not instructions. It says what landed, what is worth arguing with, and
what is still open.

## Why this did not go through Aider

`docs/LLM-PLAN.md` gives P1-T06 to Aider, and it did not go there. The rule
(`docs/WORKFLOW.md`) is *"Architect-direct when the implementation is small,
interface-shaped, or already written and verified"*, and the deciding factor was not size:
**most of the work was establishing facts, and every one of them changed the code.**

Four things were read out of transformers.js's own source or measured by running it, and
each one would have been wrong if written from a reasonable assumption:

1. The pipeline does not resample a `Float32Array`, so the resampler had to exist.
2. `_call_moonshine` returns `{ text }` and nothing else, so Moonshine cannot report word
   timings however it is asked.
3. `onnx-community/whisper-base` **throws** on any request for word timings, so the
   catalog had to move to the `_timestamped` exports.
4. A `max_new_tokens` floor that looked obviously correct made recognition **worse**.

A brief that carried those as instructions would have been the whole implementation, and
a brief that did not carry them would have produced a provider that advertises word
timings and fails on every utterance. **This is the second task in a row that has gone
architect-direct, which is worth flagging rather than repeating quietly** — if the plan's
owner fields should reflect where the work actually goes, that is a conversation to have.

## What landed

**`packages/ml-web/src/asr/`** — the model side (ADR-11).

- `messages.ts` — the worker contract and the model catalog: four models
  (`moonshine-tiny`, `moonshine-base`, `whisper-base`, `whisper-tiny-en`), exact download
  sizes per precision, and `combinationBlocker()`, which refuses every quantised precision
  on WebGPU.
- `asr.worker.ts` — the transformers.js pipeline, resampling, and cancellation through
  `InterruptableStoppingCriteria`.
- `resample.ts` — windowed-sinc rate conversion with a Blackman window, low-passing on the
  way down.
- `create-worker.ts`, `index.ts`.

**`packages/providers/src/stt/`** — the adapters.

- `browser-stt.ts` — `BrowserSTTProvider`, the worker conversation.
- `moonshine-browser.ts`, `whisper-browser.ts` — the two configurations.
- `openai-compatible-stt.ts` — `POST /audio/transcriptions`, multipart.
- `fake.ts` — `FakeSTTProvider`, which is the only provider here that produces partials.
- `signal.ts` — one function, explained below.

**`packages/providers/src/tts/wav.ts`** gains `encodeWav`, the decoder read backwards.

**`packages/ml-web/live/stt.ts`** — the live check. **`live/asr-download.ts`** — the size
measurement.

## The decisions worth arguing with

**The Whisper catalog points at `_timestamped` repos.** The plain `onnx-community/whisper-*`
exports throw `Model outputs must contain cross attentions to extract timestamps` on any
request for word timings. The `_timestamped` exports carry the attention outputs and are
within 23 KB of the same size, so this costs nothing — but it does mean the model ids here
are not the ones anybody would have guessed.

**No `max_new_tokens` override.** An earlier version floored it at 24, reasoning that
`_call_moonshine`'s `Math.floor(seconds) * 6` is 0 under a second and would lose "yes" and
"no". Both halves were false: a 0.48 s "Yes." transcribes correctly under the model's own
budget, and the floor made Moonshine answer **"Yes, yes, yes."** — the repetition that
heuristic exists to prevent. **The fix was worse than the bug, and the bug did not exist.**

**Word timestamps are opt-in on the server adapter.** They force `verbose_json` and cost
real time on some servers. `capabilities()` therefore reports what was *configured*, not
what the endpoint might be able to do — there is no capability route on this surface to
ask.

**`languageDetection` is false everywhere in the browser.** Whisper's multilingual
checkpoints do detect a language; transformers.js 3.8.1 consumes it internally and exports
no way to read it back. Reporting `true` would promise something no caller could receive.

**A cancelled call yields nothing at all.** Not a partial, not an empty final. ADR-21 makes
being cancelled the *common* path, and the caller that cancelled is the one that decided
the audio was not a turn.

**`signal.ts` exists because of a TypeScript narrowing bug in our favour.** TypeScript
narrows `readonly aborted: boolean` and keeps the narrowing, so a second check in the same
scope is reported as impossible (TS2367). The property is genuinely mutable from outside —
that is what a cancellation signal *is* — so a call boundary is the cheapest correct fix.

**Quantised precisions are refused on WebGPU in two places**: the provider constructor (so
a settings screen can show it before the microphone is touched) and the worker's `load`
(so no caller can reach the combination by forgetting to ask).

- [ ] **Live transcription visible in the transcript panel.** Not met, and not meetable
      here: there is no transcript panel until P1-T11 and no microphone capture until
      P1-T07. What was done instead is a closed loop in node — Kokoro speaks a known
      sentence, both models transcribe it, and word error rate is computed against the
      text that was spoken. **Both models: 0% WER on both sentences.** The remaining gap is
      the UI and the microphone, not recognition.

## Verify by hand

```bash
pnpm live:stt
```

Expect `exact wer 0%` four times, `9` and `16` word times from Whisper, an empty Moonshine
result for the 48 kHz-unconverted case, and `"Yes."` from the 0.48 s clip.

## What this leaves for later

- **P1-T07** owns microphone capture and hands this an `AsyncIterable<AudioChunk>`. The
  rate it captures at is the input to `resample()`; nothing else needs to know.
- **P1-T08** already owed a WebGPU q8 check for Kokoro. It now owes the same for
  recognition: ADR-20's silent-nonsense finding is the reason quantised precisions are
  refused on WebGPU, and it has never been re-tested on this version of transformers.js.
- **P1-T11** is the transcript panel, and the done-when above closes there.
- Nothing here has been measured on WebGPU at all. Spike A's 180 ms is the only recognition
  latency this project has, and it was a different transformers.js.
