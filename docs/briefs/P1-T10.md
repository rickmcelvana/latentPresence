## What main measured first, and why it changed the task

Every earlier live check ran in node, which does not enforce CORS. From a page
(`docs/SURFACE.md`, "LLM endpoints from a browser — measured 2026-09-14"):

| Endpoint | From `http://localhost:5173` | From `https://app.latentpresence.com` |
|---|---|---|
| Ollama 0.34.0 | allowed (default origins are local hosts) | **403**, needs `OLLAMA_ORIGINS` |
| LM Studio | **blocked**: no CORS headers until "Enable CORS" / `lms server start --cors` | same |
| vLLM, llama.cpp | allowed by default (docs; not running here) | same |
| OpenRouter, DeepSeek, Kimi, Google | allowed | allowed |
| Anthropic | allowed **only with** `anthropic-dangerous-direct-browser-access: true` (the adapter now sends it) | same |
| **NVIDIA** | **blocked: no CORS headers at all**, on `/v1/models` and `/v1/chat/completions` | same |

So **NVIDIA cannot be called from any page**. ADR-29 (proposed) routes it through the
companion's `/relay` on 127.0.0.1; main builds that. The UI's job is to make each case
obvious and fixable on screen.

Two more facts the UI depends on:

- **A CORS refusal and a dead server look identical to a page** (`TypeError: Failed to
  fetch`). A second request with `mode: 'no-cors'` tells them apart. `probeEndpoint` does
  this and was checked in Chrome 152 against a running Ollama (answered), LM Studio with
  CORS off (cors-blocked), NVIDIA (cors-blocked), a closed port (unreachable) and an
  unroutable address (timeout).
- **A model list is not proof of a key.** `/v1/models` answered 200 with no key *and* with a
  bad key on **NVIDIA and OpenRouter**. DeepSeek, Kimi and Anthropic said 401; Google 403 with
  no key and **400** with a bad one. Only a real completion proves a key everywhere.

And one about the bundle: **importing `@latentpresence/providers` (the root) puts
onnxruntime's wasm in the production build and the build guard fails.** Import from
`@latentpresence/providers/web` and `@latentpresence/ml-web/voices` only (439c9f7). If the
build guard fires, you imported the wrong entry — do not touch `vite.config.ts`.

## What to build (all in `apps/web/src/settings/`, plus `App.tsx` and `theme.css`)

### 1. The settings document — `settings.ts`

One JSON document in `localStorage` under `latentpresence.settings.v1`, validated on load
(add `zod` `^4.5.4` to `apps/web`, the version protocol uses). Corrupt or missing → defaults,
never a crash. **It never contains a key** — keys live in the vault, referenced by a fixed
ref per slot.

```ts
interface Settings {
  version: 1;
  companionUrl: string;                      // default DEFAULT_COMPANION_URL
  llm: {
    endpoint: string | null;                 // preset id | 'anthropic' | 'google' | 'custom'
    baseUrl: string;                         // preset default, editable; ignored for anthropic/google
    modelId: string | null;
    temperature: number | null;              // null = server default; never 0 (below)
  };
  tts:
    | { kind: 'kokoro-browser'; voiceId: string; speed: number }
    | { kind: 'openai-compatible'; baseUrl: string; model: string; voiceId: string; speed: number };
  stt:
    | { kind: 'moonshine-browser'; model: 'moonshine-tiny' | 'moonshine-base' }
    | { kind: 'whisper-browser'; model: 'whisper-base' | 'whisper-tiny-en' }
    | { kind: 'openai-compatible'; baseUrl: string; model: string; language: string | null };
}
```

Defaults: no LLM chosen; Kokoro browser with `KOKORO_DEFAULT_VOICE` at speed 1; Moonshine
tiny. Key refs: `llm:<endpoint>` (so switching presets keeps each one's key), `tts`, `stt`.

Rules carried from earlier tasks (tests for each):
- **Temperature is never 0.** Offer "Server default" (null) or a slider **0.1–1.5**. A thinking
  model at 0 spent its whole budget reasoning and wrote nothing (P1-T02/T03).
- **Speed 0.75–1.25**, step 0.05. Above ~1.25 the server's phonemes degrade (P1-T05).
- **No precision picker** for Kokoro. Quantised Kokoro is broken on WebGPU (ADR-20).
- Hide `embeddingOnly` models from the model picker. `capabilities: null` means *unknown* —
  show "capabilities unknown", never a guess (ADR-22).

### 2. The key vault — `vault.ts`

WebCrypto, measured working in Chrome 152 across a reload (2026-09-14):

- One **non-extractable** AES-GCM 256 `CryptoKey` (`generateKey(..., false, ['encrypt',
  'decrypt'])`), stored as-is in IndexedDB (`latentpresence-vault`, store `keys`, id
  `master`). A `CryptoKey` survives structured clone into IndexedDB; `exportKey` on it throws
  `InvalidAccessError`.
- Ciphertext in `localStorage` under `latentpresence.keys.v1`: `{ [ref]: { iv, data } }`,
  base64, **a fresh 12-byte IV on every write**.
- API: `saveKey(ref, secret)`, `loadKey(ref): Promise<string | null>`, `hasKey(ref): boolean`,
  `forgetKey(ref)`, `forgetAll()`.
- If decryption fails (IndexedDB cleared, localStorage kept), `loadKey` returns null and
  removes the entry; the UI then says the saved key could not be read and asks again.
- Put the IndexedDB access behind a two-method port (`getMaster`, `putMaster`) so tests run
  on an in-memory port with node's `crypto.subtle`. The real IndexedDB adapter stays thin;
  main checks it in the browser.

**Say what it protects, on screen, once, in plain words** — near the key fields: *"Keys are
encrypted in this browser's storage. Anything running on this page, or anyone using this
browser profile, can still use them."* That is the truth: it defeats copying localStorage
out of a profile or a backup, not an attacker on the page.

Never render a saved key back. A saved key shows as "Key saved" with **Replace** and
**Forget**. Key inputs are `type="password"`, `autoComplete="off"`, `spellCheck={false}`.
Never log a key, never put one in a URL, never in the settings document.

### 3. The panel — `SettingsPanel.tsx` and sections

A `/settings` route that **ships in production** (not dev-gated): add `SETTINGS_PATH` to
`App.tsx`, load the page with `lazy()` (the AI SDK is most of an 830 kB chunk; the boot screen
should not wait for it), and link it from the boot screen for everyone. Build the content as
a `SettingsPanel` component so Phase 2 can mount it inside `.drawer`.

Three sections: **Language model**, **Voice** (TTS), **Hearing** (STT). Plus a small
**Companion** field (URL, default `http://127.0.0.1:8787`) shown only when the chosen LLM
endpoint is `relay`.

**Language model:**
1. Endpoint picker: the eight presets, then Anthropic, Google, and "Custom (OpenAI-compatible)".
   Picking a preset fills its base URL (editable, except Anthropic/Google which have none).
2. Key field when `requiresApiKey`, or Anthropic/Google, or custom (optional there). Show the
   preset `hint` under it.
3. What reaching it needs, before any test. Show it from `browserAccess`: `local-cors` → one
   line saying this server may need CORS turned on; `relay` → "Calls go through the companion on
   this computer" plus the companion URL field.
4. **Test connection** (below).
5. Model picker filled from the test's model list (Anthropic/Google: their catalogs, which
   `listModels()` returns with no network call).
6. Temperature: "Server default" or 0.1–1.5.
7. **Send a test message**, enabled once a model is picked (below).

**Voice:** browser Kokoro (voice select from `toTtsVoices()`, grouped or labelled by language;
speed) or an OpenAI-compatible server (base URL, key, model, voice — a voice list from
`listVoices()` when the server has one, else a text field — speed). For browser Kokoro, say
it runs on this computer's GPU and **downloads the first time a call starts, after you agree**
(consent is P1-T13; this page must fetch no model). For a server: **Test connection**, and a
**Play sample** that synthesises "Hello, can you hear me?" and plays it through an
`AudioContext` (24 kHz is what the adapter decodes; create the context on the click).

**Hearing:** Moonshine (tiny/base) or Whisper (base/tiny-en) in the browser, same download
note — or an OpenAI-compatible server (base URL, key, model, language or "detect") with
**Test connection** (probe `${baseUrl}/models`).

### 4. Test connection — `connection.ts` (pure) + the button

Make the decision logic a pure function, tested as a table; the button just runs it.

For an LLM endpoint:
1. If `browserAccess` is `relay`: probe `${companionUrl}/health` first. Not `answered` 200 →
   show `corsHelp(endpoint, origin)` (it says "Start the companion: pnpm companion") and stop.
   Otherwise do the rest with `fetch: relayFetch(companionUrl)`.
2. Probe the listing URL with the key's headers:
   - OpenAI-compatible: `GET ${baseUrl}/models`, `Authorization: Bearer <key>` if any.
   - Anthropic: `GET https://api.anthropic.com/v1/models`, `x-api-key`, `anthropic-version:
     2023-06-01`, `anthropic-dangerous-direct-browser-access: true`.
   - Google: `GET https://generativelanguage.googleapis.com/v1beta/models`, `x-goog-api-key`.
3. Map the result to one message (and help, when there is some):

| Probe | Message |
|---|---|
| answered 2xx | "Connected." then load models via the provider's `listModels()`; show the count |
| answered 401 / 403, or 400 from Google | "The key was refused." (403 with no key saved: "This endpoint needs a key.") |
| answered 404 | "Nothing at this address. The base URL usually ends in /v1." |
| answered other | "The server answered <status>." |
| cors-blocked | `corsHelp(...)` summary and steps; for a custom endpoint with no help: "The server is running but does not allow this page (<origin>). Allow that origin in its CORS settings." |
| unreachable | local host: "Nothing is answering at <url>. Is <label> running?"; otherwise "Could not reach <host>. Check the address and your connection." |
| timeout | "No answer within 5 seconds from <url>." |

   **For NVIDIA and OpenRouter, "Connected" must add: "The key is checked when you send a test
   message."** (Their model list answered a bad key with 200.)

**Send a test message:** stream `{ modelId, messages: [{ role: 'user', content: 'Reply with
one word: ready' }], tools: [], temperature: <setting>, maxOutputTokens: null }` with a
running seconds counter and a **Cancel** (abort the signal). Show the text as it streams.
Outcomes: text arrived → "Replied in N.N s"; **`finish` with reason `length` and no text →
"The model spent its whole output budget thinking and wrote nothing. Pick a non-thinking
model, or one with a larger output limit."** (LM Studio took 89.7 s to do exactly this);
a thrown error → its message; `reason: 'error'` → "The model reported an error."
Reasoning deltas are not shown as the reply.

Local host means `localhost`, `127.0.0.1`, `0.0.0.0` or `[::1]`.

## Tests (land with the code)

jsdom + Testing Library, as `App.test.tsx`. Inject fetch/probe/provider factories through
props or a small context, so no test touches the network.

- **settings:** defaults on empty and on corrupt JSON; round trip; temperature 0 and speed
  outside 0.75–1.25 rejected or clamped by the schema; **the stored JSON never contains a
  saved key's text** (save a key, serialise settings, assert absence).
- **vault** (in-memory port): round trip; two saves of one secret give different ciphertext;
  forget; a lost master key → `loadKey` null and the entry gone; nothing plaintext in
  `localStorage`.
- **connection:** the table above, one case per row, plus the relay path (companion down →
  companion help; companion up → probe goes through `relayFetch`), the NVIDIA/OpenRouter
  key caveat, and the `length`-with-no-text outcome.
- **panel:** picking LM Studio fills `http://127.0.0.1:1234/v1`; a cors-blocked test shows
  "Enable CORS"; picking NVIDIA shows the key field and the companion field; a saved key is
  never in the DOM (`container.innerHTML` does not contain it); the model picker hides
  embedding-only models; the temperature control cannot reach 0; the speed control is bounded.
- `App.test.tsx`: `/settings` renders the panel (it is lazy — await it).
