# P1-T12 — Persona v1 and tag protocol

- **lane:** main (the whole task: its correctness is what real models do with the prompt)
- **status:** brief written 2026-09-14, after a six-turn pilot on two models and a fix the
  pilot forced (67dd675). Not started.
- **must close:** ADR-23, explicitly (promote, amend or replace the core-local tag types).

## The plan line

> *System prompt template (name, voice, style, boundaries, tag protocol description), persona
> file format (`*.persona.json`), default persona.*
> *Done when: the LLM reliably emits tags in a 20-turn scripted test with two different models.*

## What is already known (`docs/SURFACE.md`, "System prompts and inline tags")

- **No system prompt had ever reached a model.** AI SDK 7 throws before the request when
  `messages` holds a `system` message. Fixed before this brief (`toAiPrompt` → `instructions`),
  so `ChatSession`'s `system` option now works on every adapter.
- **A strong model follows the grammar as written.** `nvidia/nemotron-3-super-120b-a12b`: six
  of six replies opened with one on-list `[emote:x]`, no leaked markup, one gesture in twelve
  replies across both models. Tags go at the start of the reply, not mid-reply where the feeling
  changes.
- **A small local thinking model fails on output, not tags.** `qwen3.5:9b` returned **no text on
  3 of 6 turns** (30–36 s spent reasoning inside a 1500-token budget) and answered once **in
  Chinese**. When it wrote, it tagged correctly.
- **The grammar already exists and is parsed**: `SentenceChunker` lifts
  `^\[(emote|gesture):([a-z][a-z0-9-]*)\]` out of spoken text into `InlineTag`s with an offset
  into the chunk (`packages/core/src/chunker`). Emotes have a vocabulary —
  `CharacterEmotionSchema`, twelve labels (`packages/protocol/src/affect.ts`). **Gestures have
  none.**
- **The transcript shows raw tags while streaming** (`assistant.token` is raw; the settled line
  is tag-free). `docs/ui/transcript.md` says P1-T12 fixes that.

## Decisions this task has to make (take the recommendation, flag it, propose an ADR)

1. **Tag grammar: keep `[emote:x]` / `[gesture:x]`.** The pilot shows it followed, the chunker
   parses it, and the transcript note and RESEARCH already describe it. Alternatives (XML-ish
   `<emote>`, JSON side channel, tool calls) cost more tokens or streaming latency for nothing
   the pilot asked for.
2. **A gesture vocabulary, closed and small.** Proposed from the pilot: `nod, shake-head, shrug,
   wave, tilt-head, lean-in, open-hands, think`. Add `CharacterGestureSchema` beside
   `CharacterEmotionSchema` and give `InlineTag` a `known` for gestures too. **Flag for Rick**:
   P2-T03's clip library has to cover exactly these, so the list is partly an art decision.
3. **ADR-23: promote the tag shape into the protocol, on `assistant.sentence`.** P2-T07 schedules
   tags at audio offsets per sentence, and `assistant.sentence` already carries the chunk's index
   and tag-free text — add `tags: InlineTag[]` (kind, value, known, offset), additive with a
   default of `[]`. A separate `assistant.tag` event was the alternative; it would duplicate the
   sentence index and arrive in a different order from the text it belongs to. `PROTOCOL_VERSION`
   unchanged if additive; say so in the ADR.
4. **Tokens stop carrying tags.** A small incremental `TagFilter` in core (same grammar and the
   same 48-character scan limit as the chunker; hold back a possible partial tag at the end of a
   delta) used by `Reply`'s `token` events and `ChatSession`'s tokens. Unknown bracketed text that
   is not a tag passes through as speech, as the chunker already does.
5. **Persona format: a zod `PersonaSchema` in `packages/protocol`** (files are read by the app now
   and by the companion and memory later — `SelfModelBlock` in `memory.ts` is its future
   editable form). Proposed v1 fields: `version: 1`, `id`, `name`, `summary` (one paragraph: who
   she is), `style` (short lines: how she talks), `boundaries` (short lines: what she will not
   do or claim), `voice` (`{ voiceId, speed }` — a Kokoro id for now, overridable in settings),
   `expressiveness` (`{ gestures: 'rare' | 'some' | 'often' }`). Keep it that small; P3 adds mood.
6. **Where persona files live:** `personas/alice.persona.json` at the repo root (content, not
   code; shareable), imported by the app as JSON. Recommend; confirm Vite and `tsc -b` accept it.
7. **The template is a pure function in core**: `renderSystemPrompt(persona, context)` →
   string, with `context` holding only what is true now (the current date and time; later the
   user's name, mood, memories). Snapshot-test it.

## What the prompt must say, from the pilot

- Who she is, on a **video call**, and that **everything is spoken aloud and acted** — so short
  spoken sentences, no markdown, no lists, no emoji, no stage directions (`*smiles*`,
  `(laughs)`), numbers and symbols written the way they are said.
- **Reply in the language the user wrote in.** (The Chinese reply.)
- The tag rules: one emote near the start, **another where the feeling changes**, gestures
  "when a gesture would help" with the expressiveness level; only the listed labels; never
  describe a feeling or gesture in words instead.
- Boundaries: honest about being an AI when sincerely asked; no medical, legal or financial
  authority; no pretending to have seen, done or remembered what she has not. **Rick reviews the
  default persona's wording** — it is voice and character, not only engineering.

## The done-when, made measurable

`pnpm live:persona` in `packages/providers/live/` (hand-run, never gated, keys from `.env`,
a missing key skips): the default persona, **20 scripted user turns** with history — greetings,
good news, bad news, a factual question, list-bait ("give me five tips…"), a long-answer request,
a joke, a boundary probe ("are you a real person?"), a non-English message, a one-word reply —
against **two models**, written to `live/out/persona.md`.

**"Reliably", per model:**
- **20/20 turns produce spoken text** (no empty replies; `maxOutputTokens: null`).
- **≥ 18/20 turns carry at least one well-formed tag**, and **every** tag parses.
- **≥ 95 % of tags are on-list** (the rest are reported by label, not silently dropped).
- **0 leaks** into spoken text: bracketed non-tags, `*…*`, parenthesised stage directions,
  markdown list lines, emoji, headings.
- The non-English turn is answered in that language.

**The two models:** `nvidia/nemotron-3-super-120b-a12b` (pilot: 6/6), and **an Ollama model
that does not starve on thinking** — check `gemma4:12b-it-qat` (local) and
`nemotron-3-nano:30b-cloud` (Ollama's cloud) first, both on Rick's Ollama; `qwen3.5:9b` is the known failure and is worth keeping in the
report as the counter-example. Record the choice and why in SURFACE.

## Wiring

- `/chat` loads the default persona, passes `renderSystemPrompt(...)` as `ChatSession.system`,
  and shows `persona.name` instead of the `'Alice'` constant (two places: `ChatPage`,
  `VoiceHarness`).
- The settings voice default stays `KOKORO_DEFAULT_VOICE` unless the persona's `voiceId` is
  chosen deliberately; do not silently override a user's saved voice.
- Nothing in `/dev/voice` changes beyond the name: its model is scripted.

## Tests (land with the code)

`PersonaSchema` accepts the default file and rejects the obvious bad ones; the template renders a
stable snapshot and includes every listed label; `TagFilter` on split-across-delta tags, a
partial tag at stream end, a non-tag bracket, and the 48-char limit; `Reply` and `ChatSession`
tokens are tag-free while `assistant.sentence` carries the tags; the transcript reducer never sees
a tag; `CharacterGestureSchema` membership in `InlineTag.known`.

## Not in this task

Persona editing UI, multiple personas in settings, mood in the prompt (P3-T03), memory blocks
(P4), avatar reactions to tags (P2-T07), per-provider TTS emotion hints.
