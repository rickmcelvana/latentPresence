# P1-T13 — Model download consent

- **lane:** sub (a subagent the architect runs in-session), with the two turn workers
  reviewed closely — see *Where this gets dangerous*.
- **status:** brief written 2026-09-22, after reading the installed `@huggingface/transformers`
  and `onnxruntime-web` call sites. Not started.
- **hard rule it implements:** `CLAUDE.md` — *"Ship no models. Nothing downloads without the
  consent screen (size, licence, source)."* And ADR-09.

## The plan line

> *Consent modal listing model, size, licence, source URL before any browser model download;
> cache in Cache Storage; a settings page to delete caches.*
> *Done when: no network fetch of weights occurs before consent (verified in Playwright by
> intercepting requests).*

## Two decisions already taken, so you do not have to

**1. No Playwright in this task.** The plan says to verify in Playwright and the repo has
none — adding it means a new devDependency, a browser download and CI changes, for one
assertion. P1-T14 is *"Playwright test feeding synthetic audio through a virtual mic"*, so
the harness arrives there where an end-to-end test justifies it, and **P1-T14 re-asserts this
claim in a real browser then**. Until then the claim is proven two cheaper ways, both of
which you write: a vitest test that the gate is *structural* (below), and a note in the
session log that the browser leg is owed. Do not add Playwright.

**2. No protocol change.** `ModelDescriptor` and `ProviderDescriptor.requiresDownload`
already exist and already say in their own doc comments that they feed this screen. All four
descriptor factories ship: `kokoroModel(dtype)`, `asrModel(key, dtype)`, `sileroVadModel()`,
`smartTurnModel(build)`. **You must not touch `packages/protocol`.** If you believe it needs
a field, stop and say so instead.

## What is actually true about downloading (read from source, 2026-09-22)

The full note is in `docs/SURFACE.md`, "What actually downloads weights, and where it caches".
The part that shapes the work:

**There are two download paths and only one of them caches.**

1. **transformers.js, and kokoro-js through it.** Caches into Cache Storage under the name
   **`transformers-cache`**, on by default in a browser. Covers Moonshine, Whisper, Kokoro
   and Smart Turn's `WhisperFeatureExtractor`. A cache it cannot open is **warned about and
   ignored**, so a private window silently re-downloads instead of failing.
2. **onnxruntime-web, directly.** `vad.worker.ts:30` and `smart-turn.worker.ts:56` pass a
   **URL** to `InferenceSession.create(...)`, and ort fetches it itself. **We never see that
   request**: it cannot be shown to a user first and it never reaches `transformers-cache`.

**So "no fetch before consent" cannot be implemented by wrapping `fetch`.** The gate is
structural in both cases: for path 1, *do not construct the pipeline*; for path 2, *do not
create the session from a URL*. A test that stubs `globalThis.fetch` proves nothing about
either, because neither goes through a `fetch` you own.

## The work

### 1. A consent gate in `packages/ml-web`

A small module — suggested `packages/ml-web/src/consent/` — with no DOM in it:

- `ModelConsent`, backed by `localStorage` through an injected `Storage` (follow
  `apps/web/src/settings/` for the dependency-injection style already used here):
  `has(descriptors): boolean`, `grant(descriptors): void`, `revoke(): void`, and
  `granted(): readonly string[]`. Consent is per `ModelDescriptor.id`, which already encodes
  the precision (`onnx-community/Kokoro-82M-v1.0-ONNX:fp32`) — **agreeing to the 92 MB `q8`
  must not agree to the 325 MB `fp32`.**
- `requireConsent(consent, descriptors)` throws a named, catchable error naming the models
  that were not agreed to. Every worker-creating entry point calls it **first**.

### 2. Make the two turn workers fetch their own bytes

This is the only part that changes behaviour rather than adding to it.

- `createSileroSession` already takes `string | Uint8Array`. Add the same to
  `createSmartTurnSession` if it does not have it.
- In `vad.worker.ts` and `smart-turn.worker.ts`, replace `InferenceSession.create(url)` with:
  fetch the bytes through a **cached fetch** helper, then create the session from the bytes.
- The cached fetch helper (suggested `packages/ml-web/src/consent/model-cache.ts`): look in
  `caches.open('latentpresence-models')`, return the cached `Response` body when present,
  else fetch, `cache.put`, and return. **Wrap every Cache Storage call in try/catch and fall
  back to a plain fetch** — transformers.js swallows this failure for a real reason (private
  windows, iframes), and a hard failure here would mean no voice in incognito rather than a
  slow one.
- **Check the fetched byte length against the descriptor's `sizeBytes` and fail loudly if it
  differs.** `packages/ml-web/live/turn.ts` already does exactly this against the catalog —
  copy its approach. A weight file that changed size is not a file we should hand to ort.

### 3. The consent screen

A component in `apps/web/src/consent/`, shown before anything that needs weights:

- One row per model: label, size (MB, one decimal), licence, and the source URL as a real
  link with `rel="noreferrer"`. A total at the bottom.
- The plainest possible statement of what is about to happen: these are downloaded from
  Hugging Face to this computer, they stay in this browser, nothing is sent anywhere.
  (`docs/ui/transcript.md` is the house voice to match.)
- **Agree** and **Cancel**. Cancel leaves everything untouched and the caller must handle it.
- Style it in `theme.css` with the teal tokens the day you write it, and add every new
  className to `theme.test.ts` — that test keeps every className styled and it will fail
  otherwise.

### 4. `/settings`: a Downloaded models section

In `apps/web/src/settings/`, beside the existing sections:

- List what is cached now, with sizes, read from the caches rather than from what was agreed.
- **Delete** per cache and **Delete all**, hitting both `transformers-cache` and
  `latentpresence-models`, and revoking consent when everything is deleted.
- Say plainly that deleting means the next use downloads again.

### 5. Wire the callers

`/dev/voice` (`VoiceHarness.tsx`) already has an "Agree and start" button and a
`downloads()` list — **replace its ad-hoc screen with the real one** rather than leaving two.
`/settings`'s voice and hearing sections pick browser models, so those paths need the gate
too. `/chat` gains voice in a later task and is not your concern.

## Tests, landing with the code

- `ModelConsent`: grants per id; a different precision of the same model is **not** granted;
  `revoke` clears; a broken `Storage` (throws on read and on write) degrades to "not granted"
  rather than crashing.
- `requireConsent` names every ungranted model in its message.
- The cached fetch: a miss fetches and puts; a hit does not fetch; a `caches` that throws
  falls back to a plain fetch; a body whose length disagrees with `sizeBytes` throws.
- **The structural gate, which is the done-when:** for each of the four worker entry points,
  a test that with no consent recorded it throws *before* constructing anything — assert on
  a `fetch` spy **and** an `InferenceSession.create` spy having zero calls. That second spy
  is the one that matters; see the note above about `fetch` proving nothing.
- The consent screen: renders every field of every descriptor, the total, Cancel calls back
  without granting, Agree grants exactly the ids shown.
- `theme.test.ts` stays green.

## Where this gets dangerous

**The two turn workers are the risky change**, because they are on the hot path P1-T07 and
P1-T08 measured: Silero runs every 32 ms and Smart Turn answers in 8–57 ms warm. Changing how
their sessions are created must not change what they do.

- Keep `createSileroSession`'s existing wasm-only execution provider and
  `ort.env.wasm.numThreads = 1` exactly as they are.
- Keep the Smart Turn backend selection (`gpu`/`int8` rules, ADR-21) untouched — int8 on
  WebGPU is refused for measured reasons and that logic is not yours to revisit.
- The worker warms up at load (P1-T07's finding: the first inference was 392–479 ms and landed
  late). **Warm-up must still happen, and must now happen after consent.**

If any of this forces a change to the turn detection logic itself, stop and say so.

## Not in this task

Download progress bars; resuming a partial download; a model picker beyond what `/settings`
already has; LLM or server-side providers (they download nothing); P1-T14's Playwright leg;
bundling weights (we never will — ADR-09).

## Done when

- No weights are fetched before consent, proven by the structural test above.
- Both caches are listed and deletable from `/settings`.
- `pnpm gate` green, and `/dev/voice` still reaches a working voice after agreeing.
