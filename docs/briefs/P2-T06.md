## Decisions already taken

**1. `/chat` becomes the call. No new route.** The page is: the stage filling the viewport,
a controls bar along the bottom, the transcript in a drawer on the right, the user's camera
as a PiP in the bottom-left corner. Typed and spoken turns stay one conversation on one
machine and one history, exactly as now — do not change how `ChatSession`, `attachHistory`
or `VoicePanel`'s state machine work, only where things sit. The unconfigured branch
("choose a model in Settings") stays as it is.

**2. The stage is a lazy chunk, `apps/web/src/call/CallStage.tsx`**, imported with
`lazy()` from `ChatPage` exactly like `VoicePanel` (no `import.meta.env.DEV` guard — it is
production). three.js and three-vrm must not be in `/chat`'s own chunk: a person who never
shows the character never fetches them.

**3. The character is behind consent, and cached.** The placeholder VRM is VRM Public
License, fetched at run time from `AVATAR.downloadUrl` (`spikes/avatar-consent.ts`). Before
consent the stage shows a panel in the frame: the character's label, size, licence, source
and author, **Show the character** / **Not now**. Use `ConsentScreen` if its wording fits an
asset that is not a model; if it says "model" in a way that would be false, give it an
optional heading/intro prop rather than writing a second screen. Mechanics:
- one `ModelDescriptor` for the avatar (`id: 'pixiv/VRM1_Constraint_Twist_Sample.vrm'`,
  `sizeBytes: AVATAR.bytes`, licence, sourceUrl) in a new
  `apps/web/src/call/character-asset.ts`; **move `AVATAR` there** and have
  `spikes/avatar-consent.ts` re-export it, so the dev pages keep working unchanged;
- `ModelConsent` (the same `latentpresence.consent.v1` store) remembers the agreement, so a
  returning user is not asked again;
- the bytes come through `cachedModelFetch(url, descriptor)` (size-checked, Cache Storage,
  falls back to a plain fetch), then `URL.createObjectURL(new Blob([bytes]))` is handed to
  `loadCharacter`, and revoked after the load.
- **Not now** leaves an empty, lit stage with a small "Show the character" button in the
  frame; the conversation works exactly as it does today.
Nothing is fetched before agreement — a test proves it with a fetch spy.

**4. The frame loop** (in `CallStage`): `LifeLayer.update` → `setLifePose`, `LipSync.update`
→ `setViseme`, `renderer.update`. `LifeLayer.setState` follows `machine.getState()` via
`machine.subscribe`. Camera preset **`medium`** by default. Take `delta` capped at 100 ms is
already in the life layer; do not add another cap.

**5. Lip sync needs the call's output node.** Add a read-only `get output(): AudioOutputHandle`
to `VoiceCall`, add an optional `onCallStarted?: (call: ActiveCall & { output?: … }) => void`
(or equivalent — your call on the shape) from `VoicePanel` up to `ChatPage`, and when a call
starts `CallStage` builds `new LipSync(tapAnalyser(output.context, output.node))`; when the
call ends it drops it and sets every viseme to 0. Keep the `ActiveCall` test seam working
(a fake call has no audio graph — make `output` optional on the interface).

**6. Mute.** `VoiceCall.setMuted(muted: boolean)`: stop feeding frames to the VAD while
muted (the capture callback checks a flag — do not stop and restart the microphone, and do
not touch `packages/providers`' capture). A muted mic must also mean no barge-in and no
backchannel, which falls out of the VAD hearing nothing. The **Mute** button is enabled only
during an active call and shows its state (`aria-pressed`).

**7. Controls bar** — one row, centred, over the bottom of the stage, buttons from the
existing `.btn` styles plus a new icon-less round variant if you want one (text labels are
fine; no icon dependency):
- **Start voice / End call** (drives the existing `VoicePanel` flow; the panel's consent and
  "starting" states render as a card above the bar, not inline in a column);
- **Mute** (6);
- **Camera** — toggles the PiP (8);
- **Text** — shows/hides the text box, which docks above the bar; hidden and disabled during
  a call exactly as the textarea is disabled now;
- **Transcript** — opens/closes the drawer; open by default at ≥ 1440 px wide, closed below;
- a **Settings** link.

**8. User camera PiP, no processing.** `getUserMedia({ video: true, audio: false })` on the
Camera click, into a muted, `playsInline`, mirrored (`transform: scaleX(-1)`) `<video>` in a
rounded box bottom-left, 16:9, `width: clamp(160px, 14vw, 480px)`. Stopping it stops every
track. Nothing reads its pixels — no canvas, no recorder, no upload; say so in a comment. A
refusal shows one line in the PiP's place and turns the button off. Put the stream handling
in a small `useUserCamera()` hook with an injectable `getUserMedia` so jsdom can test it.

**9. The transcript drawer** is `TranscriptPanel` unchanged, inside an `<aside>` on the right,
`width: clamp(320px, 26vw, 640px)`, full height above the bar, overlaying the stage (the
stage does not resize when it opens — a canvas resize every toggle is a visible hitch).
Closed = `hidden`, not unmounted, so scroll position survives.

**10. Responsive, 1024 px to 4K.** The page is `100dvh`, no page scroll. Sizes scale with
`clamp()` against the viewport so a 4K screen does not get 1080p-sized controls in the
middle of a sea. The renderer's pixel ratio: `min(devicePixelRatio, 2)` and never a drawing
buffer wider than 3840 — compute it in a pure helper (`call/pixel-ratio.ts`) with a test,
and re-apply it on resize. Below 1024 px nothing has to look designed, but nothing may
overlap unusably either.

**11. The build guard.** `/chat` now mounts the renderer, so `@pixiv/three-vrm` and
`three/examples/jsm` come **out** of `vite.config.ts`'s forbidden list, and its comment is
updated to say so (P2-T06). Replace them with needles only the avatar dev pages carry —
`@react-three/fiber` for `/spike/avatar` if it really is only there (grep), and a string only
`AvatarDebug.tsx` contains. **Mutation-check both** (temporarily make each dev route
reachable in production, confirm `pnpm --filter web build` fails, revert) and report that
you did.

## Repo gotchas that will otherwise cost you a gate run

- `erasableSyntaxOnly`: no constructor parameter properties.
- `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` are on.
- oxlint: `toSorted()` not `sort()`; `addEventListener` not `onfoo =`; helpers that capture
  nothing at module scope; no setState synchronously in an effect; no ref reads during render.
- `theme.test.ts` scans string literals inside `className` templates — compute a
  conditional class into a variable first. Every new class needs a rule in `theme.css`, with
  the existing tokens only (no colour literals outside `:root`).
- StrictMode runs mount effects twice in development: a renderer disposed by the first
  cleanup must not start a loop (see `AvatarDebug`'s `cancelled` flag), and a callback prop
  must never be an effect dependency that tears down a call (see `ChatPage`'s comment on
  `onVoiceActive`).
- Match the surrounding comment style: comments say *why*, in full sentences.
