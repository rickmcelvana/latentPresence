## Decisions already taken

**1. One pure module: `packages/avatar/src/affect/`** (`regions.ts`, `body.ts`, `index.ts`,
tests beside them), three-free, exported from the package root. **`packages/avatar` must not
import `@latentpresence/core`** — it depends on protocol only, and stays that way. So the
input is plain data the page assembles:

```ts
export interface AffectInputs {
  readonly mood: Mood;               // protocol
  readonly energy: number;           // 0..1
  readonly stance: SocialStance;     // protocol
  /** The strongest current feeling — the page gets it from core's `dominantEmotion`. */
  readonly feeling: { readonly label: CharacterEmotion; readonly intensity: number };
}
```

**2. Regions are Mehrabian's PAD octants plus neutral.** `affectRegion(mood)`:
`'neutral'` when every PAD component has `|x| < NEUTRAL_RADIUS` (0.25 — the default baseline,
pleasure 0.2, must classify neutral); otherwise the octant by the signs of P, A, D:

| P A D | region | | P A D | region |
|---|---|---|---|---|
| + + + | `exuberant` | | − + + | `hostile` |
| + + − | `dependent` | | − + − | `anxious` |
| + − + | `relaxed` | | − − + | `disdainful` |
| + − − | `docile` | | − − − | `bored` |

A component of exactly 0 counts as +. `regionStrength(mood)` = distance of the mood from the
origin beyond `NEUTRAL_RADIUS`, scaled so 1 is reached at a PAD length of 1, clamped 0..1
(0 in `neutral`).

**3. One table, `REGION_BODY: Record<AffectRegion, RegionBody>`**, each entry:

- `face: ExpressionWeights` — a *resting* face for the region at full strength, **every weight
  ≤ 0.35** (the emote on top of it is the strong one). `neutral: {}`. Use the VRM presets and
  the brow/eye extras the protocol names; e.g. exuberant `{ happy: 0.3 }`, relaxed
  `{ relaxed: 0.3 }`, anxious `{ browInnerUp: 0.3, sad: 0.1 }`, hostile `{ angry: 0.25 }`,
  bored `{ sad: 0.15, relaxed: 0.1 }` — your judgement for the rest, one line of why each.
- `gaze: GazeModulation` — multipliers on the life layer's per-state `MoodParams`:
  `{ lookAwayScale, holdScale, awayMeanScale, blinkScale, breathScale }` (all 1 = unchanged),
  plus optional `awayTargets` replacing the state's list (e.g. `bored`/`docile` look `down`
  more, `anxious` looks `away` more and blinks faster, `exuberant` holds the user's eyes
  longer). `blinkScale` scales *the mean interval* (>1 = fewer blinks); say so in the type's doc.
- `gestureBias: CharacterGesture[]` — ordered, most fitting first, 2–4 entries, **performable
  ones first** (`GESTURE_MOTIONS[g] !== null`).
- `idleClip: string` — the clip id this region would idle on. Only `'idle'` exists
  (`apps/web/src/call/clips.ts`); name the ones a later pack would add (`'idle-bright'`,
  `'idle-low'`, `'idle-tense'` — your call) and let the function fall back.

**4. `affectToBody(inputs, availableClips = ['idle']): AffectBody`** — the one function:

```ts
export interface AffectBody {
  readonly region: AffectRegion;
  readonly strength: number;                 // 0..1
  readonly expression: ExpressionWeights;    // what the face should rest at, before tags
  readonly gaze: GazeModulation;             // identity at strength 0, energy 0.5, engagement ≤ 0
  readonly gestureBias: readonly CharacterGesture[];
  readonly idleClip: string;                 // always one of availableClips
  readonly idleClipWanted: string;           // the table's choice, for the panel to show a fallback
}
```

- **expression** = region face × strength, merged by per-name **max** with
  `EMOTION_EXPRESSIONS[feeling.label]` × `feeling.intensity`, every weight capped at 0.8.
- **gaze**: each multiplier lerped from 1 towards the region's value by `strength` (and
  `awayTargets` only once strength ≥ 0.5); then **stance and energy** on top:
  `lookAwayScale *= 1 − 0.4 × max(0, stance.engagement)` (engaged → looks away less);
  `breathScale *= 0.85 + 0.3 × energy`; `blinkScale *= 1.15 − 0.3 × energy`. Put these
  constants in a named, commented object, not inline.
- **gestureBias**: the region's list; if `stance.engagement > 0.5` and `'lean-in'` is not
  first, put it first.
- **idleClip**: `idleClipWanted` if in `availableClips`, else `availableClips[0]`.

**5. `modulateMood(base: MoodParams, gaze: GazeModulation): MoodParams`** in the same module,
clamping: `lookAwayChance` to 0..0.95, every `…Ms` ≥ 300, `breathsPerMinute` 6..30.
`LifeLayer` gets **`setModulation(gaze: GazeModulation | null)`**, applied in `update()` as
`modulateMood(this.params.moods[this.state], …)`. With `null` (the default) nothing changes —
**the same seed must give the same frames as before**; test it.

**6. The panel — "Affect" on `/dev/avatar`**, a new `<section className="panel">` after
"Life", shown only when the character is loaded, as the others are:

- **Source:** `sliders` or `engine`.
  - *sliders:* pleasure, arousal, dominance (−1..1), energy (0..1), warmth and engagement
    (−1..1), a feeling select (the 12 `CharacterEmotion`s) and its intensity (0..1).
  - *engine:* a real core `AffectEngine`, ticked in the frame loop with `performance.now()`
    mapped to wall time; buttons fire an `emotion` input (intensity 0.6, source `internal`)
    for each emotion; the readout shows P/A/D/energy decaying live. `feeling` comes from
    `dominantEmotion(state)`.
- **Review:** a select of **exactly ten named states** that sets the sliders (and switches the
  source to sliders): `neutral` (the core baseline), `exuberant`, `relaxed`, `dependent`,
  `docile`, `hostile`, `anxious`, `disdainful`, `bored`, and `joy flash` (baseline mood, joy at
  intensity 0.9). Pick PAD values that sit clearly inside each octant (|component| ≈ 0.6) and a
  matching feeling each (e.g. anxious → concern 0.5). Put the list in a small exported
  constant in its own file (`apps/web/src/dev/affect-review.ts`) so the review is reproducible.
- **Live readout** (sampled twice a second like the Life readout): region, strength,
  expression weights, the gaze multipliers, gesture bias, and idle clip (`idle (wanted
  idle-low)` when it fell back).
- **Apply:** a checkbox "Drive the character" (default on when the panel is used). While on:
  the frame loop sets the face to `affect.expression` merged by per-name max with the
  performer's cue expression (tags still show on top), and calls
  `life.setModulation(affect.gaze)`; off → `setModulation(null)` and the page behaves exactly
  as today. "Perform bias" button: performs `gestureBias[0]` through the page's
  `CuePerformer` as a gesture tag.
