# P4-T02 — Companion memory API (brief)

**Owner:** sub (a subagent the architect runs in-session). **Depends:** P4-T01 (done).
**Done when:** OpenAPI generated from the zod schema matches; integration tests pass in CI
with a MariaDB service container.

You are implementing the companion's memory routes in Rust, over a schema and a contract that
already exist. Read this brief, then the files it names; do not redesign what they decide.

## Routes to implement

Exactly these from `companionRoutes`; leave ingest, MCP and schedules unimplemented (no route).

| Route | Does |
|---|---|
| `health` | `database.kind` `"mariadb"` and `connected` true when a pool is up; `"none"`/false with no `DATABASE_URL`; `"mariadb"`/false if connecting failed. |
| `dbRegisterEmbeddingModel` | `register_model`, then `ensure_collection` for all three collections; any collection with no active model gets this one activated. Returns `modelId` (the integer as a string) and each collection's status. |
| `dbActivateCollection` | `register_model` (idempotent) then `activate_collection`; `not_found` if that collection has no table for the model. |
| `dbAppendEpisode` | Upsert the session by `sessionId` (uid; `started_at` = the episode's `at` if new, `character_id` from the episode). Insert the turn (`uid` = `id`, `seq` = next in the session, computed in the same transaction). Writing an id that exists is idempotent: same id, same row, no error (the kernel may retry). `affect` → the `user_affect` JSON column. With an `embedding`: register its model, `ensure_collection(Turns, …)`, activate it if the collection has no active model, and upsert the vector into that table (`INSERT … ON DUPLICATE KEY UPDATE embedding = VALUES(embedding)`). |
| `dbUpsertFact` | Insert or update by `uid`. `sourceEpisodeId` → `source_turn` by looking up the turn's uid (unknown → `bad_request`). `embedding` as for episodes, collection `Facts`. |
| `dbSupersedeFact` | Set `valid_to` on the fact with that uid; `not_found` if none. Nothing is deleted. |
| `dbReadBlocks` | Every block for `characterId`, ordered by `label`. |
| `dbWriteBlock` | Upsert by (`character_id`, `label` = `name`); `value` = `content`; bump `version`; `bad_request` if the content is over `char_limit` (the table's CHECK would refuse it — say so first, in words). |
| `dbListPlans` | Every plan for `characterId`, newest `updated_at` first, with its tree: phases are `plan_items` with `kind='phase'` and no parent, ordered by `position`; tasks are `kind='task'` children, ordered by `position`; a task's `notes` is `body` (`''` when null). |
| `dbSavePlan` | New `uid`: insert with the given `version` (must be 1). Existing: the request's `version` must be the stored version + 1, else `conflict` (409). Replace the items wholesale in one transaction (delete, insert phases then tasks). |
| `dbRetrieve` | Below. |

Every error body is `CompanionError` with HTTP status: `bad_request` 400, `not_found` 404,
`conflict` 409, `unavailable` 503 (no database), `database` 502, `internal` 500. Request bodies
that fail to parse are `bad_request` with serde's message. **No error may contain the
connection string** (see `DbError` and its test in `crates/db/src/lib.rs`).

### Retrieval — one statement

ADR-17: one round trip to the database per turn. Build **one SQL statement** as a `UNION ALL`
of parenthesised branches, each selecting the same three columns — `kind` (a string literal),
`rank` (a number: distance for vector hits, 0 for others) and `body` (`JSON_OBJECT(...)` with
the row's fields) — and turn the rows into the bundle in Rust:

- **episodes, vector** (only when `queryEmbedding` is present and its model is the active one
  for `turns`): nearest-first in a derived table over the active `turn_embeddings_<id>`, `LIMIT`
  over-fetched (`max(32, 4 × limit)`), joined to `turns`, filtered to `character_id`, **not the
  current `sessionId`** (the kernel holds this session's turns itself), and `created_at >=
  since` when given; `ORDER BY` distance, `LIMIT limits.episodes`.
- **episodes, keyword**: `MATCH(text) AGAINST(? IN NATURAL LANGUAGE MODE)` on `turns` with the
  same filters, `LIMIT limits.episodes`. Skip the branch when `query` is blank.
- **facts, vector** and **facts, keyword** the same way over `facts` / the active
  `fact_embeddings_<id>`, current facts only: `expired_at IS NULL AND (valid_to IS NULL OR
  valid_to > UTC_TIMESTAMP(3))`.
- **blocks**: every block for the character.
- `documents` is `[]` until P5.

Merge in Rust: per kind, vector hits first by distance, then keyword hits not already present,
cut to the limit. `vectorSearch` is `used`, `no-query-embedding`, `no-active-model` (the query
has an embedding but `turns` has no active collection) or `other-model` (its model is not the
active one). `elapsedMs` is the time spent in the statement. Episodes and facts come out with
`embedding: null`. Every value goes in as a bind (`?`); only the vector table names — built by
`vector_table_name` from integers — are formatted into the SQL, behind `AssertSqlSafe`.

### Times

The protocol's timestamps are ISO-8601 with `Z` or an offset; the tables hold `DATETIME(3)` in
UTC. Convert at the edge (parse, normalise to UTC; format out as `…Z` with milliseconds). Add
sqlx's `time` or `chrono` feature — whichever you choose, add it to the workspace dependency and
say which in your report.

## Rules

- **Static-table SQL uses `sqlx::query!` / `query_as!` / `query_scalar!`** (ADR-35), so it is
  checked at build time against `companion/crates/db/.sqlx`. After adding or changing one,
  refresh the cache against the dev database: from `companion/crates/db`, with
  `SQLX_OFFLINE=false` and `DATABASE_URL` set from the repo's `.env` (read the value from the
  file; **never print it**), run `cargo sqlx prepare`. Only the vector tables' statements and
  the retrieval `UNION` may be dynamic.
- Where the code lives is your call, but database access belongs in `crates/db` (a `store`
  module is the obvious place) and HTTP in `crates/server` (a `memory_api.rs` module).
- The server starts with or without a database; the pool comes from `DATABASE_URL` in the
  environment or the repo's `.env` (`bench::database_url` already reads both — share it rather
  than copying it). Connecting runs the migrations.
- Check that the CORS middleware lets a browser page send `PUT` and `POST` with
  `content-type: application/json` (a preflight) to these routes; extend it if not, with a test.
- **Never commit, never edit `packages/protocol`**, never print or log `DATABASE_URL`.

## Tests

- **Unit tests** that need no database, in the gate: time conversion both ways, the error
  mapping to status and code, the retrieval SQL builder (which branches appear for which
  request, and that no request value is formatted into the SQL), plan tree assembly.
- **Integration tests** in `companion/crates/server/tests/memory_api.rs` that drive every
  implemented route through the router against a real MariaDB. They run only when
  `LP_TEST_DATABASE_URL` is set, and otherwise return early with an `eprintln!` saying they were
  skipped (so the gate passes on a machine with no database). Each test uses its own
  `character_id` (`test-<random>`) and deletes what it wrote. **Validate every 200 body against
  its `components.schemas` entry and every error body against `CompanionError`**, using the
  `jsonschema` crate on `include_str!` of the committed OpenAPI file — that is the done-when's
  "matches". Cover at least: register a model (first becomes active); append episodes with and
  without embeddings, and the same id twice; retrieve with vector and keyword hits, excluding
  the current session, and each `vectorSearch` reason; upsert and supersede a fact and see it
  leave retrieval; blocks round trip and the over-limit error; plan save, list, the version
  `conflict`; `unavailable` with no pool; deleting a session removes its turns' vectors.
- Run them yourself against the dev database: `LP_TEST_DATABASE_URL` from the repo's `.env`.
- Add to CI's `vector` job (`.github/workflows/ci.yml`) a step running `cargo test
  --manifest-path companion/Cargo.toml --workspace` with `LP_TEST_DATABASE_URL` set to the
  service container's URL, after the existing steps.
- `pnpm gate` green (it runs `cargo fmt --check`, `clippy -D warnings` and the tests).
