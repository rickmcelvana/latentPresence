# P4-T04 — MemoryStore adapters (brief)

**Owner:** sub (a subagent the architect runs in-session). **Depends:** P4-T02, P4-T03 (done).
**Done when:** the adapter conformance suite passes for both implemented stores (companion/MariaDB
and IndexedDB).

You are writing two `MemoryStore` adapters and a stub, in TypeScript, against an interface, a
conformance suite and a companion that already exist. Read this brief, then the files it names;
do not redesign what they decide. **Never edit `packages/protocol`, never commit.** If
something in the contract or the suite looks wrong, stop and say so in your report rather than
working around it.

## What already exists — read these first

  comments: writes must not depend on being awaited; reads for a turn are one `retrieve`.
- `packages/protocol/src/companion.ts` — `companionRoutes`: method, path, query, request and
  response schema for every route, and `CompanionErrorSchema`. The companion implements
  `health`, every `db*` route, and nothing for schedules yet.
- `packages/core/src/memory/conformance.ts` — **the suite you must pass**, exported as

  lists the rules. `fake-store.conformance.test.ts` shows how a store runs it.
- `packages/core/src/memory/errors.ts` — `MemoryStoreError(code, message)`. Every refusal an
  adapter throws is one of these; the suite checks `code`.
- `packages/core/src/memory/fake-store.ts` — `FakeMemoryStore`, which passes the suite. Its
  `retrieve` is the local search the IndexedDB store needs (see below).
- `companion/crates/server/src/memory_api.rs` — how the companion answers (status codes,
  error bodies). `docs/memory.md` for the kernel that will call you.
- `packages/providers/src/web.ts` — the model-free entry the production app imports. Read its
  header: nothing it exports may reach `@latentpresence/ml-web`.

## 1. Shared local search (core)

Move the ranking inside `FakeMemoryStore.retrieve` — word overlap, cosine, "vector hits first,
then keyword hits, deduplicated, limited", the active-model rule, current-fact filter — into
`packages/core/src/memory/local-search.ts` as pure functions over plain arrays (no store, no
I/O), exported from the memory index. `FakeMemoryStore` then calls them; its behaviour must not
change (all existing core tests stay green, the replay snapshot unchanged). Unit-test the
functions directly. The IndexedDB store calls the same functions, so the two cannot drift.

## 2. `CompanionMemoryStore` — `packages/providers/src/memory/companion.ts`

`new CompanionMemoryStore({ baseUrl, fetch? })` — `baseUrl` is the companion's origin
(settings' `companionUrl`, e.g. `http://127.0.0.1:8787`); `fetch` defaults to
`globalThis.fetch` bound, injectable for tests. `id` is `'mariadb'`.

- **One private `call(routeName, { query?, body? })`** that reads everything from
  `companionRoutes[routeName]`: method, path, query string from `query` (URL-encoded), JSON
  body. No path or method literal anywhere else in the adapter.
- **Every response is parsed** with the route's `response` schema — a companion can be an
  older build than the page (the contract module's header says so). A 2xx that does not parse
  is `MemoryStoreError('internal', …)` naming the route and saying the companion may be a
  different version.
- **Errors:** a non-2xx body that parses as `CompanionErrorSchema` becomes
  `MemoryStoreError(error.code, error.message)`; one that does not parse becomes `internal`
  with the HTTP status in the message. A rejected `fetch` (nothing listening, CORS) is
  `unavailable`, message naming the URL and asking whether the companion is running.
- `capabilities()` needs no network: `{ vectorSearch: true, dimensions: null,
  bitemporalFacts: true, plans: true, schedules: false, remote: true }` (`remote`: every call
  is a round trip, ADR-17).
- `retrieve` → `dbRetrieve`; `appendEpisode` → `dbAppendEpisode`; `upsertFact`;
  `supersedeFact(id, validTo)` → `{ id, validTo }`; `expireFact(id, at)` → `{ id, at }`;
  `currentFacts(characterId)` → `dbCurrentFacts`, returns `.facts`; blocks and plans likewise.
- **Schedules:** the companion has no schedule routes yet. `listSchedules`, `saveSchedule`,
  `deleteSchedule` throw `MemoryStoreError('unavailable', 'this companion does not keep
  schedules yet')` without a request.

Tests (`companion.test.ts`), with an injected `fetch` that records requests and answers
canned responses: each method's method, path, query and body (read the expected values from
`companionRoutes`, not literals); an error body → the same code; a garbled 2xx → `internal`;
a garbled error → `internal` with the status; a rejected fetch → `unavailable`; schedules
never fetch.

**Conformance against a real companion** (`companion.conformance.test.ts`): runs the suite
with `vectors: true` against `process.env.LP_TEST_COMPANION_URL`, and **skips** (the suite's
`skip` option, with a reason) when it is unset — `pnpm gate` has no companion. The architect
runs it against the dev MariaDB.

## 3. `IndexedDbMemoryStore` — `packages/providers/src/memory/indexeddb.ts`

For the browser on its own (ADR-05). `new IndexedDbMemoryStore({ indexedDB?, name?, now? })` —
`indexedDB` defaults to `globalThis.indexedDB` (injectable: tests pass `fake-indexeddb`'s
`IDBFactory`, never a global polyfill); `name` defaults to `'latentpresence-memory'`. `id` is
`'indexeddb'`.

- Open lazily on first use, once (a cached promise). Version 1 creates object stores
  `episodes`, `facts`, `blocks`, `plans`, `schedules` (each with a `characterId` index; blocks
  keyed by `[characterId, name]`), and `collections` (the active model per collection: `turns`,
  `facts`, first writer wins, as in the fake and the companion).
- Store vectors beside their rows (a separate field, never returned); `retrieve` loads the
  character's rows by index and ranks with `local-search.ts` — **brute force** is the plan's
  word, and fine at a person's scale.
- The same rules and error codes as the fake: idempotent `appendEpisode`; `not_found`;
  `bad_request` for an end before a beginning; `conflict` for a plan version out of step;
  current facts by `Date.parse` against `now()`.
- Every write is one transaction; a method resolves when its transaction completes.
- `capabilities()`: `{ vectorSearch: true, dimensions: <active turns model's> or null,
  bitemporalFacts: true, plans: true, schedules: true, remote: false }`.

Add `fake-indexeddb` (Apache-2.0) as a **devDependency of `@latentpresence/providers`**.
Tests: the conformance suite (`vectors: true`) on a fresh `IDBFactory`; data written through
one instance is read by a second instance on the same factory and name (it persists); two
names do not share data.
