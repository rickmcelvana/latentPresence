## What to build

### 1. Wiring in `ChatPage.tsx`

- Keep the attached memory in **React state** as well as `memoryHolder` — set both where the
  effect attaches it, clear both in its cleanup — along with the choice's `reason` (what store
  it is: "this browser", "the companion at …"). `null` means memory is off or not ready.
- The drawer shows **one of two views**: transcript (as today) or memory. A new **Memory**
  button in `call-controls-bar`, beside Transcript, opens the drawer on the memory view;
  Transcript opens it on the transcript view; pressing the button of the view already showing
  closes the drawer. Each button's `aria-pressed` is true only while the drawer shows its view.
  The drawer's default open/closed rule (`DRAWER_OPEN_AT_PX`) is unchanged, on the transcript.

### 2. `apps/web/src/memory/MemoryPanel.tsx`

Props: `memory: AttachedMemory | null`, `where: string | null`, `characterName: string`.

- **Header:** "Memory" and one line saying where it is kept (`where`), or, with `memory` null,
  a sentence saying memory is off and that Settings → Memory turns it on (link `/settings`).
- **"What she was told last"** — `memory.lastInjected()`: the facts (via `factLine`) and the
  earlier turns it carried, and when. "Nothing yet" before the first request. Refresh it
  whenever the panel is opened and after each message (subscribing to the machine's
  `assistant.message` is fine — the page already has `machine`).
- **"What she knows"** — `kernel.knownFacts()`, surest first. Each fact: its line, and
  **Edit** and **Delete**.
  - Edit turns the line into one text input for the object (subject and predicate shown, not
    edited) with Save / Cancel; Save calls `memory.correctFact({ ...fact, object })`.
  - Delete asks once, in place ("Forget this for good?" with a confirm and a cancel button —
    no `window.confirm`), then calls `memory.deleteFact(id)` and removes the row.
- **"Conversations"** — `kernel.listEpisodes(null)`, newest first, grouped by `sessionId` with
  the session's first time as the group heading; **Older** loads the next page
  (`listEpisodes(oldest.at)`) and disappears when a page comes back short of 50. Each turn:
  who said it (the user / `characterName`), the text, "(interrupted)" when it was, and
  **Delete** with the same in-place confirm, calling `memory.deleteEpisode(id)`.
- **Search:** one text input above Conversations; on submit (Enter or a button) with text,
  the list shows `kernel.searchEpisodes(query)` instead, with a way back to the full list.
  Facts are filtered client-side by the same text (case-insensitive, over `factLine`).
- Every async action shows a busy state on its own control and, on failure, the error's
  message in a line under that section (a `MemoryStoreError`'s message is written for people).
  Never let one failed call blank the panel.

Loading happens when the panel mounts (it mounts when its view is shown), not at page load.

### 3. Tests — `apps/web/src/memory/MemoryPanel.test.tsx`

With a real `MemoryKernel` + `attachMemory` over `FakeMemoryStore` (no mocks of the API):
null memory shows the off sentence and the Settings link; facts listed surest first; edit →
save changes the store; delete asks, cancel keeps it, confirm removes it **and the next
`kernel.recall` does not return it** (the done-when, through the UI); conversations grouped
by session, Older pages; a turn deleted; search shows `searchEpisodes` results; a store that
throws shows its message and keeps the rest. In `ChatPage.test.tsx`: the Memory and
Transcript buttons switch the drawer's view and `aria-pressed` as described.
