## What to build

### 1. `apps/web/src/settings/ToolsSection.tsx` (in `SettingsPanel`, after Memory)

Heading "Tools". One sentence: tools come from MCP servers you add; she asks before using one
unless you say otherwise; nothing is sent to a server until she uses one of its tools.

- **Servers list**: each server shows its label, URL, transport, an **on/off** switch, **Test**,
  and **Remove** (confirm in place, like the memory panel — no `window.confirm`). Remove drops
  the server and its grants, and clears its token (add `deleteKey(ref)` to `Vault` in
  `vault.ts`, with a test — that file is app code and yours to extend).
- **Add a server**: label, URL, transport (Streamable HTTP / SSE; default HTTP), auth (None /
  Bearer token). With Bearer, a `KeyField` saving to `mcpKeyRef(id)`. The id is minted once
  (`crypto.randomUUID()`). Refuse an empty label or a URL that does not parse as http(s).
- **Test** calls `connectToolServer` (injectable `connect` prop for tests, default
  `connectMcpServer`; `loadKey` from `deps.vault`) and shows "Connected — N tools" or the
  failure, then lists the server's tools: name, description (clamped to two lines, expandable),
  and a **policy select**: Ask first / Always allow / Never. Choosing Always allow stores
  `{ policy: 'auto', fingerprint: toolFingerprint(tool) }`; Ask and Never store a null
  fingerprint. A tool whose saved `auto` fingerprint no longer matches shows "Changed since you
  allowed it — she will ask again" (use `effectivePolicy`).
- Grants and servers change through the panel's normal settings state and save path, so the
  section never writes storage behind the panel's back.

### 2. `apps/web/src/chat/PermissionPrompt.tsx` (rendered by `ChatPage`)

Props: `prompts: PermissionPrompts`, `characterName: string`. Read with `useSyncExternalStore`.
Nothing rendered when nothing is waiting. For the **oldest** waiting ask, a card docked above the
controls bar (like `.call-voice-card`, above the text box, below any open consent card):

- "`<characterName>` wants to use **`<serverName>`** · `<tool>`", the tool's description, and the
  arguments as formatted JSON in a `<pre>` (scrolls when long).
- When `changed`: a warning line — "This tool has changed since you allowed it."
- Buttons **Allow once**, **Always allow**, **Deny** → `prompts.answer(id, 'once'|'always'|'deny')`.
- "+N more waiting" when more than one is pending.
- `role="alertdialog"` with `aria-labelledby`/`aria-describedby`; move focus to Allow once when
  it appears only if focus is not in the text box (never steal focus from someone typing).

## Tests

- `ToolsSection.test.tsx`: add a server (with and without a token — the token lands in the
  vault, never in settings), refuse bad input, toggle, remove with confirm (grants and token
  gone), Test with a fake `connect` listing tools (`FakeMcpServer` from
  `@latentpresence/providers/web`), set each policy and see the stored grant (auto carries the
  fingerprint), the "changed" note, a failing Test shows its message.
- `PermissionPrompt.test.tsx`: renders the oldest ask, each button answers it, the changed line,
  "+N more", nothing when empty.
- `ChatPage.test.tsx`: with the `connectTools` seam returning a `FakeMcpServer` ("DeepWiki",
  tool `read_wiki_structure`) and a scripted model that calls `deepwiki__read_wiki_structure`:
  the prompt appears; **Allow once** → the server was called, the transcript shows "Alice used
  deepwiki · read_wiki_structure" and her answer; **Deny** → the server was not called and the
  transcript says she did not use it. A `connectTools` that reports a failed server puts a
  notice in the transcript.
