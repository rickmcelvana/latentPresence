## What to build

### 1. A "Tools from the companion" block in `ToolsSection`, above "Add a server"

- `panel-title`-styled heading "From the companion", and one sentence: the companion can run
  servers listed in its own `mcp.json` (on this computer, edited by you), including a read-only
  Files server for folders you name there; they are off until you turn this on.
- A switch (same markup as a server's On/Off switch, `role="switch"`), label "Offer the
  companion's tools", bound to `tools.companion` through `onChange` as an updater.
- A **List** button (enabled whether or not the switch is on). It calls
  `connectCompanionTools({ baseUrl: companionUrl, ... })` — new props `companionUrl: string` and
  a test seam `listCompanion?` passed through — and shows, in an `aria-live` region like Test's:
  each status as a line (label, then `detail`, styled ok/danger as Test is), and under each ok
  server its tools as `ToolRow`s keyed `companion:<name>` for the grants. Pressing List again
  replaces what it showed. Nothing reaches the companion until List is pressed; like Test, List
  calls no tool and closes nothing (the companion owns its servers).
- When the switch is off, the policies can still be set (they wait for it to be turned on).

### 2. One fix you will need

`remove(id)` in `ToolsSection` rebuilds the tools object as `{ servers, grants }` and so drops
`companion`. Spread `previous` so every other field is kept; add a test that removing a server
keeps `companion: true`.

### 3. `SettingsPanel`

Pass `companionUrl={settings.companionUrl}` to `ToolsSection`.

## Tests (`ToolsSection.test.tsx`, Testing Library, as the file already does)

- The switch writes `companion: true` / `false` through `onChange`.
- List with a `listCompanion` seam returning one ready server (two tools) and one failed one
  shows "Files — 2 tools" style ok text, the failure's detail in danger style, and two policy
  selects; choosing "Always allow" writes `grants['companion:files'][tool]` with
  `toolFingerprint(info)`, as a page server's does.
- List when the seam throws shows "The companion" line with the "pnpm companion" advice.
- The remove fix above.
- Existing tests keep passing (`EMPTY` and the other `ToolsSettings` literals need
  `companion: false`).
