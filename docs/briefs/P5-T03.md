### 1. `latentpresence-ingest` — pure: no database, no network

- `extract(path: &Path) -> Result<Extracted, String>` where `Extracted { title: String, mime:
  &'static str, pages: Vec<Page { locator: Option<String>, text: String }> }`.
  - PDF: `pdf_extract::extract_text_from_mem_by_pages`, **inside `std::panic::catch_unwind`**
    (a panic is an `Err` for that file); one `Page` per PDF page, locator `p. N` (1-based).
    Title: the first non-empty line of page 1, else the file stem.
  - DOCX: open with `zip`, read `word/document.xml`, text of `w:t` elements, `\n` at the end of
    each `w:p`, `\t` for `w:tab`, entity and character references resolved. One page, no locator.
  - HTML/HTM: `html2text::from_read(bytes, 10_000)`; title from `<title>` if present.
  - MD/MARKDOWN/TXT: UTF-8 (lossy); MD title from the first `# ` line.
  - Anything else: not supported (the walker skips it before calling `extract`).
- `chunk(pages: &[Page]) -> Vec<Chunk { seq: u32, locator: Option<String>, text: String }>`:
  **chunks never cross a page.** Target 1,000 characters (count `char`s, not bytes), overlap 150;
  cut at the last paragraph break (`\n\n`) inside the window, else the last sentence end
  (`. `, `? `, `! ` followed by an uppercase letter or end), else the last whitespace, else hard.
  Whitespace inside a chunk collapsed to single spaces except paragraph breaks; empty pages make
  no chunks; `seq` counts across the document from 0.
- `sha256(bytes) -> [u8; 32]`.
- Tests: each format (build the DOCX in the test with `zip::ZipWriter`; HTML and MD as strings in
  a temp dir; the PDF fixture → two pages, `p. 1` / `p. 2`, "Basil" on page 1, "Thyme" on 2);
  a corrupt PDF (random bytes) is an `Err`, not a panic; the chunker: no chunk over 1,000 chars,
  consecutive chunks overlap, nothing lost (every word of the input appears in some chunk),
  never across pages, a 5,000-char page with no punctuation still chunks.

### 2. Migration `0004_documents.sql` and `latentpresence_db::documents`

Add to `documents`: `folder VARCHAR(2048) NOT NULL DEFAULT ''`, `path_key BINARY(32) NULL`
(SHA-256 of the full path as UTF-8; a `UNIQUE` key on it), `modified_at DATETIME(3) NULL`,
`model_id INT UNSIGNED NULL` (the `model_registry` row its chunks were embedded with; null:
keyword only), `indexed_at DATETIME(3) NULL`. Add to `chunks`: `locator VARCHAR(64) NULL`.
Functions (with `StoreError`/`DbError` like `store.rs`): list the documents under a folder
(id, source, bytes, modified_at, sha256, model_id); delete a document by id (chunks cascade;
**delete its vectors too** — check whether the per-model vector tables cascade from `chunks`, and
if not, delete them explicitly); insert a document and its chunks in one transaction; counts of
documents and chunks per folder. Use `query!`/`query_as!` on these static tables and refresh the
offline cache: from `companion/`, with the repo's `.env` providing `DATABASE_URL`,
`SQLX_OFFLINE=false cargo sqlx prepare --workspace` (sqlx-cli 0.9.0 is installed). Commit-ready
means `.sqlx` has every new query.

### 3. The server: `crates/server/src/ingest/`

- **Config** `documents.json`, found like `mcp.json` (`mcp::config::config_path` — generalise it
  to take the file name and the env var; `COMPANION_DOCUMENTS_CONFIG`):
  ```json
  {
    "folders": ["C:/Users/me/Documents/manuals"],
    "embedding": {
      "baseUrl": "http://127.0.0.1:11434/v1",
      "model": "nomic-embed-text",
      "dimensions": 768,
      "documentPrefix": "search_document: ",
      "queryPrefix": "search_query: ",
      "headers": {}
    },
    "watch": true
  }
  ```
  `embedding` optional (absent: keyword only); `watch` default true; unknown top-level fields an
  error. No file: no folders. A file that does not parse: `configError` in the status, no
  folders. Folders are canonicalised at start; one that does not exist is reported
  `exists: false`.
- **Embedding client:** `POST {baseUrl}/embeddings` `{ model, input: [documentPrefix + text, …] }`,
  32 inputs per request, headers from the config, 120 s timeout; read `data[].embedding` by
  `index`; a vector whose length is not `dimensions` fails the job with that said. Register the
  model with `provider` = `baseUrl` (the `EmbeddingModelRef` shape the store already uses) and
  write each chunk's vector with the existing `embed_item` path for `Collection::Chunks` (make what
  you need from `store.rs` public rather than copying it).
- **A job** (one at a time; `IngestJob` from the contract, kept in memory with the last one): for
  each folder, walk it (no symlinks, skip names starting with `.`, extensions `.pdf .docx .html
  .htm .md .markdown .txt` case-insensitive, skip files over 100 MB); compare with what the
  database has under that folder:
  - same size and modified time, and `model_id` matches the configured model (or both none):
    unchanged — not read;
  - else read and hash: same hash and model → update `modified_at` only; else delete the old
    document and index the file (extract in `spawn_blocking`, chunk, embed, insert);
  - in the database but not on disk: delete, count `documentsRemoved`.
  A file that fails is a `failures` entry (first 100) and the job goes on; the job `failed` only
  when it cannot go on (no database, the embedding endpoint refusing). `documentsSeen` counts
  supported files found.
- **When:** a job at start (trigger `start`) when there are folders and a database; on a change
  under a watched folder (`notify::recommended_watcher`, recursive), after 3 s with no further
  change (trigger `watch`); on `POST /ingest/scan` (trigger `request`) — if a job is running,
  answer that job instead of starting another.
- **Routes** in `companionRoutes` shapes (camelCase, as `memory_api.rs` does): `GET
  /ingest/status`, `POST /ingest/scan`, `GET /ingest/jobs/:id` (the running or last job; any other
  id `not_found`). No database: `/ingest/scan` answers `unavailable` (`ApiError::Unavailable`).
- `main.rs`: load the config, start the ingester with the pool, print one line like the MCP one
  ("documents from …: N folder(s), embedding <model> | keyword only").

### Tests (Part A)

Unit tests for the config (shapes, errors, defaults) and the walker (skips). Integration tests
in `crates/server/tests/ingest_api.rs` against MariaDB, skipping like `tests/memory_api.rs` does
