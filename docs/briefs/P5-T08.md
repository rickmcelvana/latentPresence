## 1. Content and layout — `packages/avatar/src/stage/displays.ts` (three-free, pure)

```ts
export interface WhiteboardContent {
  readonly title: string;
  /** In order: a phase is a heading; a task has done true/false. */
  readonly lines: readonly { readonly text: string; readonly kind: 'heading' | 'task'; readonly done: boolean }[];
}
export interface ScreenContent {
  readonly heading: string; // e.g. "Sources"
  readonly items: readonly { readonly title: string; readonly where: string | null; readonly text: string }[];
}
export interface Displays { readonly whiteboard: WhiteboardContent | null; readonly screen: ScreenContent | null }
```

- `layoutBoard(blocks, measure, box)`: wraps words to the box width with an injected
  `measure(text, font) => width`, cuts a word longer than a line with "…", stops at the box
  height and ends with a "+N more" line when anything was left out. Returns positioned lines
  (`{ text, font, x, y, colour role }`). Pure, tested in node with a fake measure (e.g. 0.55 ×
  font size per character).
- Text sizes are in **board metres**, converted to texture pixels by the texture's pixels per
  metre: body text **0.032 m** (3.2 cm) tall, titles **0.05 m**, line height 1.35 ×. Export
  them (`BOARD_TEXT`), because the readability test uses them.
- Whiteboard: title, then for each phase a heading line and its tasks as "☐ task" / "☑ task"
  (done struck through or muted; `dropped` tasks left out), at most 3 phases shown.
- Screen: heading, then up to 3 items: title (bold), `where` (muted, small — the site or
  "p. 12"), then the first ~140 characters of `text`, one blank line between items.

## 2. The objects — `packages/avatar/src/vrm/stage.ts` (+ a small `vrm/display-board.ts`)

- **Positions (ADR-49, measured):** back wall face at z = −2.17 (2 cm off the wall, as the window
  is). Whiteboard centre (−1.27, 1.45), surface **0.84 × 0.62 m**, a thin frame. Screen centre
  (1.27, 1.45), surface **0.84 × 0.50 m**, a dark bezel ~3 cm. **Move the window**: centre x
  **2.4**, frame **1.1 m** wide (pane narrower to match), height unchanged.
- Named `whiteboard`, `whiteboard-surface`, `screen`, `screen-surface` (tests and the debug
  panel find parts by name).
- Every new colour in `STAGE_PALETTE` (board white, frame, marker ink, a teal marker accent for
  titles, bezel, screen background, screen text, screen muted). The canvas reads its colours from
  the palette (hex → `#rrggbb`), no literals elsewhere.
- Surfaces: the whiteboard a `MeshStandardMaterial` with `map` = its `CanvasTexture`
  (roughness ~0.5); the screen lit from within — `MeshBasicMaterial` (or standard with
  `emissiveMap`) so it reads at the same brightness under any light. `colorSpace =
  THREE.SRGBColorSpace`, `anisotropy` from the renderer's max, mipmaps on.
- Texture resolution: 1024 px wide, height by the surface's aspect.
- **Drawing** (`display-board.ts`): `drawBoard(ctx, layout, palette)` — fills the background and
  draws the positioned lines with `system-ui, sans-serif` (nothing downloaded). In node there is no
  canvas, so `buildStage` must not need one: create the canvas lazily through an injected
  `createCanvas(width, height)` (the renderer passes `document.createElement('canvas')`); with
  none, the surfaces are plain materials and nothing is drawn.

## 3. The renderer and the call

- `VrmAvatarRenderer.setDisplays(displays: Displays)`: lays out, redraws the two canvases and sets
  `texture.needsUpdate = true`, only when the content changed (compare a cheap key, e.g. JSON).
  `null` content: whiteboard blank white; screen off (its background only, darker).
- `CallStageRenderer` gains optional `setDisplays?(displays: Displays): void`; `CallStage` takes a
  `displays` prop and passes it on change (and once after the character loads).
- `ChatPage` builds `displays`:
  - **whiteboard**: from `plans` — subscribe to the store; the plan whose id is
    `promptContext().focusId`, else the newest (`updatedAt`) plan whose status is not `archived`;
    null when there are none. Put the pure mapping `planToWhiteboard(plan)` in
    `apps/web/src/call/displays.ts`.
  - **screen**: the latest assistant transcript line with `citations.length > 0`; each ref through
    `citationSource` (unknown refs skipped); `sourcesToScreen(sources)` in the same file, `where`
    = the source's `locator` (documents: "p. 12"; web: the site). null when none.

## 4. Tests (these are the done-when, in node)

- `displays.test.ts`: wrapping, cutting a long word, "+N more", phases/tasks/dropped, screen items
  and the 140-character cut.
- `stage.test.ts`, new — **the readability proof**: with `framing('medium', STANDARD_BODY)` and
  a 30° vertical FOV, for **1920×1080 and 1920×1200**: project each board's four corners
  (a `THREE.PerspectiveCamera` at the framing's position looking at its target, `aspect` set,
  `updateMatrixWorld`, `Vector3.project`) and assert every corner is inside NDC [−1, 1]; assert
  each board's projected rectangle does not overlap the projection of the existing
  `STANDING_PERSON_BOX` or of the moved window; and assert that **body text (`BOARD_TEXT`'s body
  height) projects to ≥ 16 px** at 1080p (project two points 3.2 cm apart vertically at the
  board's centre). Keep the existing desk test passing.
- `CallStage.test.tsx`: `displays` reaches `setDisplays`. A `ChatPage`/`displays.ts` test for
  `planToWhiteboard` (focus wins; archived skipped) and `sourcesToScreen`.
- `theme.test.ts` must still pass (no new classNames are expected — this is all in the scene).
