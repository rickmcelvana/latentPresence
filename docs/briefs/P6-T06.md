## 1. Packs — `apps/web/src/characters/packs.ts`

```ts
export interface CharacterPack {
  readonly persona: Persona;          // parsed with PersonaSchema at module load, like default-persona.ts
  readonly avatar: AssetDownload;     // from call/character-asset.ts
  readonly avatarDescriptor: ModelDescriptor;
}
export const PACKS: readonly CharacterPack[];          // Alice first, then Theo
export const DEFAULT_CHARACTER_ID = 'alice';
export function packFor(id: string | null | undefined): CharacterPack; // unknown → Alice's pack
```

- Both packs use `AVATAR` / `AVATAR_DESCRIPTOR` (the placeholder body) until P7.
- Keep `default-persona.ts` exporting `defaultPersona` (other code and tests use it); it may
  re-export Alice's persona from the packs.
- Test (`packs.test.ts`): every pack's persona parses, ids are unique, `packFor('nobody')` is Alice.

## 2. Settings — `settings.ts`

Add to `SettingsSchema`, both with defaults so an old document still loads:

```ts
character: z.string().min(1).default('alice'),
characters: z.record(z.string(), z.object({
  voice: z.object({ kind: z.enum(['kokoro-browser', 'openai-compatible']), voiceId: z.string().min(1), speed: SpeedSchema }).nullable(),
})).default({}),
```

- **Migration** in `loadSettings`: when the stored JSON has no `characters` key and its `tts` is
  `kokoro-browser` with a `voiceId` different from Alice's persona voice, set
  `characters.alice = { voice: { kind: 'kokoro-browser', voiceId, speed } }` — someone who picked a
  voice for Alice keeps it. Tested.
- `characterVoice(settings, persona): { voiceId: string; speed: number }` (in
  `apps/web/src/characters/voice.ts`): the saved choice for `persona.id` if its `kind` equals
  `settings.tts.kind`; else, when the engine is `kokoro-browser`, the persona's `voice`; else
  `settings.tts.voiceId` / `speed`. And `withCharacterVoice(settings, persona): Settings` — a copy
  whose `tts.voiceId` and `tts.speed` are `characterVoice(…)`. Tested for every branch.

## 3. `/chat` — `ChatPage.tsx`

- **Split the component**: today's body becomes an internal `ChatRoom` taking the same props
  plus `pack: CharacterPack` and `onSwitch: (id: string) => void`. The exported `ChatPage(props)`
  reads `loadSettings(deps.storage).character` once into state, and renders
  `<ChatRoom key={pack.persona.id} pack={pack} … />`. `onSwitch(id)` saves `character` (load,
  change, `saveSettings`) and sets the state, so the room remounts: a new session, everything
  built for the new character.
- In `ChatRoom`, every `defaultPersona` / `CHAT_CHARACTER_NAME` use becomes `pack.persona` /
  `pack.persona.name` — the system prompt, `characterId` everywhere (machine, affect, kernel,
  notes, plans, `lastConversation`, the inner monologue's `character`), the rest label, the panels'
  `characterName`, the face-reading intro, the permission prompt. Keep exporting
  `CHAT_CHARACTER_NAME` (= Alice's name) for existing tests.
- **Voice**: wherever `settings` flows into the speaker (`loadSpeaker`/`Speaker.start`) and the
  voice panel (`VoicePanel`'s `settings`), pass `withCharacterVoice(settings, pack.persona)`.
- **Avatar**: `CallStage` loads `pack.avatar` / `pack.avatarDescriptor` — add props for them
  (defaulting to `AVATAR` / `AVATAR_DESCRIPTOR` so `/dev` pages and tests are unchanged).
- **Switcher**: in the control bar, before Transcript, a labelled `<select>` "Talking to" with one
  option per pack (`aria-label="Talking to"`, class `call-character-select`). Disabled while a voice
  call is open (`voiceOpenRef`/the voice panel state) or an answer is streaming (`chat.busy`, read
  however the page already reads it for the Stop button). Changing it calls `onSwitch`.
- `document.title` is not touched.

## 4. Settings → Character — `CharacterSection.tsx`

A section in `SettingsPanel`, placed just before Voice: heading "Character", a `<select>` of the
packs (writes `character`), the active persona's `summary` as a muted note, and "Voice for
{name}": when the engine is `kokoro-browser`, a `<select>` of the Kokoro voices (the same list and
grouping `VoiceSection` uses — export it from there rather than copying) with a first option
"{name}'s own ({persona voice id})" meaning no saved choice (`voice: null`); for
`openai-compatible`, a text input for the voice id, blank meaning "the one in Voice". Saving writes
`characters[id].voice` with the current engine's `kind`. Tested like `InitiativeSection`'s test in
`settings.test`/`SettingsPanel.test`.

## 6. The done-when test — `ChatPage.test.tsx`, a new `describe('ChatPage — characters (P6-T06, ADR-55)')`

One `FakeMemoryStore` shared by every mount through `chooseMemory` (one database). A scripted
provider that answers chat requests with text, and answers **extraction** requests (their system
prompt is the memory extractor's — find how `ChatPage.test` or `packages/core/src/memory` tells
them apart) with a fact about what was said. Then:

1. As Alice (default), type "my sister is called Mira"; wait until the store has a current fact
   for character `alice` mentioning Mira.
2. Switch "Talking to" to Theo. The next chat request's system prompt names Theo and does not
   contain "Mira"; `store.currentFacts('theo')` is empty; the Memory view shows no Mira.
3. As Theo, type "I play the cello"; wait for a `theo` fact about the cello.
4. Switch back to Alice: her next request's prompt has Mira and not cello;
   `currentFacts('alice')` has no cello and `currentFacts('theo')` has no Mira.
5. Settings persisted `character` across each switch.

Plus: the switcher is disabled while an answer is streaming (use `scriptedProvider` with a gate),
and with a saved Kokoro voice for Theo the speaker gets Theo's voice (use `fakeSpeaker`).
