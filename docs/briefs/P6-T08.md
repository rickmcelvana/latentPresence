## 1. Words for a time — `packages/core/src/scheduler/words.ts`

`whenWords(at: Date, now: Date, timeZone: string): string` returns the next run as she should say
it back, in fixed English (not the machine's locale):
- `today at 21:00 (in 3 hours)`
- `tomorrow at 09:00 (in 14 hours)`
- `Thursday 15 October at 09:00 (in 1 day and 23 hours)`
- `Sunday 3 January 2027 at 08:00 (in …)` (the year only when it is not `now`'s year)

How to build it:
- Use `Intl.DateTimeFormat('en-GB', { timeZone, weekday: 'long', day: 'numeric', month: 'long',
  year: 'numeric', hour: '2-digit', minute: '2-digit', hourCycle: 'h23' })` and `formatToParts`,
  then assemble the parts yourself.
- "today" and "tomorrow" are decided by the date in `timeZone`.
- The distance:
  - under an hour: minutes (`in 1 minute`, `in 40 minutes`);
  - under a day: hours and minutes, dropping zero parts (`in 3 hours`, `in 2 hours and 5 minutes`);
  - otherwise: days and hours.

Also `repeatWords(expression: string): string | null`. It names the common shapes:
- `0 9 * * *` → `every day at 09:00`
- `30 7 * * 1-5` → `weekdays at 07:30`
- `0 18 * * 0` → `every Sunday at 18:00`
- `*/15 * * * *` → `every 15 minutes`

It returns null for anything else. The caller then shows the expression itself.

Test every example above in `words.test.ts`, including one across a clock change (`America/Chicago`
2026-11-01) and one in `Pacific/Chatham`.

## 2. The holder — `packages/core/src/scheduler/schedules.ts`

Model it on `Plans`: a snapshot that is replaced on every change, never mutated; `subscribe`; and
every write going through one queue (`tail`).

```ts
export interface ScheduleRequest {
  readonly description: string;            // 1–200 chars after trim
  readonly at?: string;                    // 'YYYY-MM-DDTHH:MM' in the person's zone
  readonly inMinutes?: number;             // whole, 1..10080
  readonly repeat?: string;                // five-field cron
  readonly task?: string;                  // empty or absent: a reminder
  readonly tools?: readonly string[];      // only with a task
  readonly delivery?: DeliveryMode;        // default 'notify'
  readonly catchUp?: CatchUpPolicy;        // default: 'run_once' for at/inMinutes, 'skip' for repeat
}
export type ScheduleOutcome = { readonly ok: true; readonly schedule: Schedule } | { readonly ok: false; readonly reason: string };

export class Schedules {
  constructor(options: {
    store: Pick<MemoryStore, 'listSchedules' | 'saveSchedule'>;
    characterId: string;
    timeZone: string;                       // the person's
    companion: boolean;                     // memory is the companion: reminders run there
    toolNames?: () => readonly string[];    // hers, now — what `tools` may name
    now?: () => Date; newId?: () => string;
  });
  load(): Promise<void>;                    // re-reads every call (the page refreshes each tick)
  snapshot(): readonly Schedule[];          // see ordering below
  subscribe(listener: () => void): () => void;
  find(ref: string): Schedule | null;       // id; else description, case- and space-insensitive, newest active first
  create(request: ScheduleRequest): Promise<ScheduleOutcome>;
  pause(ref: string): Promise<ScheduleOutcome>;
  resume(ref: string): Promise<ScheduleOutcome>;
  cancel(ref: string): Promise<ScheduleOutcome>;
  markDelivered(ids: readonly string[], at: Date): Promise<void>;   // uses markDelivered from runner.ts
}
```

**`create`:**
- Exactly one of `at`, `inMinutes` and `repeat`. Anything else is refused, and the refusal says
  which to give.
- `at` goes through `wallTimeToInstant(at, timeZone)`. Null means refuse: "not a time — give
  YYYY-MM-DDTHH:MM".
  - A result `<= now` is refused with what the time is now in `whenWords`-style words, so she can
    correct herself.
- `inMinutes` becomes `once` at `now + n min`.
- `repeat` must parse (`parseCron`; a `CronError`'s message is the reason). Its first `nextRunAt`
  is `nextFiring(trigger, now)`.
- `runOn`:
  - `'companion'` when `companion` is set and there is no task;
  - otherwise `'core'`.
- A task with a `tools` name not in `toolNames()` is refused, naming it and listing what she has.
- The schedule is saved with these values:
  - `status: 'active'`, `lastRunAt: null` and `lastRun: null`;
  - `toolCall: null` and `taskPrompt: task ?? ''`;
  - `allowedTools: tools ?? []`;
  - `createdAt` and `nextRunAt` set.

**`resume`:**
- Sets `nextRunAt = nextFiring(trigger, now)`. A paused job does not catch up on what passed.
- A one-shot whose time has passed is refused: "its time has passed — make a new one".

**`cancel`:** sets `status: 'cancelled'` and `nextRunAt: null`. It never deletes.

Pause, resume and cancel accept only these starting states. Anything else is refused in words:

| Action | Allowed from |
|---|---|
| pause | active |
| resume | paused |
| cancel | active or paused |

**Ordering for `snapshot()`:**
1. active and paused, by `nextRunAt` ascending, with paused ones after active ones;
2. then the rest, by `lastRunAt ?? createdAt` descending.

`load()` forgets a failed read, as `Plans.load` does.

## 3. Run now — `runner.ts`

Add `runNow(scheduleId: string): Promise<ScheduleRun | null>` to `AttachedScheduler`.

- It runs the schedule once at `now`, through the same `runOne` path (episode, `lastRun`, `onRun`),
  **without moving `nextRunAt` or `status`**.
- It queues behind a pass in progress (chain it on `running`) so it never overlaps one.
- The run is **delivered at once** (`deliveredAt` = finishedAt), because she reads it in the tool
  reply and says it herself.
- It returns null, and runs nothing, when:
  - the schedule is not found;
  - it has a `toolCall` (the companion's to run);
  - the attachment is detached.
- A `runOn: 'companion'` reminder may be run now by the page. It needs no model.

Add tests beside the existing `attachScheduler` ones.

## 4. Her tools — `packages/core/src/scheduler/tools.ts`

`scheduleTools(options: { schedules: Schedules; runNow: (id: string) => Promise<ScheduleRun | null>; timeZone: string; now?: () => Date }): LocalTool[]`

It follows `plan/tools.ts`: zod-parsed args, a refusal is a result and never a throw, and
`stringified` for arrays.

| Tool | Arguments | Reply |
|---|---|---|
| `schedule_create` | `description`, one of `at` / `in_minutes` / `repeat`, optional `task`, `tools`, `delivery`, `catch_up` | `{ saved: { id, description, when, repeats: repeatWords(…) ?? expression ?? null, runs_on } }` or `{ error }` |
| `schedule_list` | `include_finished?: boolean` | `{ schedules: [{ id, description, status, when, repeats, last: { outcome, summary, at } \| null }] }` |
| `schedule_cancel` | `schedule` (id or description) | `{ cancelled: { id, description } }` or `{ error }` |
| `schedule_run_now` | `schedule` | `{ ran: { outcome, summary } }` or `{ error }` |

In the replies, `when` is `whenWords(next, now, timeZone)`, or `null` once the schedule is
finished.

**Descriptions matter: the live check reads them.**

`schedule_create` must say all of the following:
- Use it for "remind me…" or "every morning…": something at a time, even when they are away.
  - This is distinct from `plan_follow_up`, which is something she raises herself in conversation.
- `at` is the time in **their** local time, worked out from RIGHT NOW: "Thursday at 9" is the
  coming Thursday's date at 09:00.
- **After saving, tell them when it will happen using the reply's `when`, word for word, not your
  own reading.** If it is wrong, cancel it and create the right one.
- Leave out `task` for a plain reminder. The description is what she will say.

Test each tool, its refusals and the `schedule_create` → `schedule_list` round trip in
`tools.test.ts`.

## 5. Telling them — `packages/core/src/scheduler/deliveries.ts`

```ts
export interface AttachDeliveriesOptions {
  readonly schedules: Schedules;
  readonly chat: Pick<InitiativeChat, 'speakUp'>;
  readonly blocked: () => boolean;           // as initiative's
  readonly visible: () => boolean;           // the page is showing
  readonly notify?: (schedule: Schedule, run: ScheduleRun) => Promise<boolean>;
  readonly timeZone: string;
  readonly scheduler?: Scheduler; readonly tickMs?: number;   // SCHEDULER_TICK_MS
  readonly now?: () => Date;
  readonly onError?: (error: Error) => void;
}
export function attachDeliveries(machine: { getState(): ConversationState }, options): { tick(): Promise<boolean>; detach(): void };
export function deliveryCue(items: readonly { schedule: Schedule; run: ScheduleRun }[], now: Date, timeZone: string): string;
```

What `tick()` does, in order:
1. `await schedules.load()`, then take `pendingDeliveries(schedules.snapshot())`.
2. While **not** `visible()`: each pending run whose schedule has `delivery: 'notify'` goes to
   `notify`. If it returns true, `markDelivered`.
3. If `visible()`, not `blocked()`, the machine is in a quiet state (`idle` or `listening`), and
   something is still pending: call `chat.speakUp(deliveryCue(rest, …))`. If that returns true,
   `markDelivered` all of them and resolve `true`.
4. Otherwise resolve `false`.

It does not overlap itself, and it never touches the initiative ledger. The timer runs as it does in
`attachInitiative`.

**`deliveryCue`** is a hidden turn in the voice of `initiativeCue`. Examples:
- One reminder: `(They asked you to remind them about this, and it is time now: "call the vet". Remind them in one or two short sentences, the way a friend would.)`
- Late, when `scheduledFor` is more than five minutes (`LATE_GRACE_MS`) before now: add
  `It was due at 09:00 this morning, while they were away — say so.` Use `whenWords`-style parts,
  past tense.
- A task's result: `(Something you did for them on a schedule finished — "summarise the inbox": <summary>. Tell them in a sentence or two.)`
- Several: one cue listing each, numbered.
- A failed run's summary already says it failed (`runner.ts`). Pass it through.

Test, with a fake chat and a fake store:
- hidden with a notify that shows: told, no speakUp;
- hidden with a notify that throws or returns false: waits;
- visible and blocked: waits;
- visible and free: one speakUp, everything told;
- speakUp returning false: nothing told;
- the late wording, and several items in one cue.

**Notifications.** Add an optional prop `notifications?: PageNotifications` to
`ConfiguredChatPageProps`, defaulting to the browser's. Put it in
`apps/web/src/chat/notifications.ts`:

```ts
export interface PageNotifications {
  permission(): 'granted' | 'denied' | 'default' | 'unsupported';
  request(): Promise<'granted' | 'denied' | 'default' | 'unsupported'>;   // only ever from a click
  show(title: string, body: string, tag: string): boolean;               // false on any throw

```

`pageNotify(schedule, run)` behaves like this:
- the page is visible: `false`, so she says it;
- not `granted`: `false`;
- otherwise `show(persona.name, run.summary, run.id)`.

## 7. The Schedules panel — `apps/web/src/schedule/SchedulesPanel.tsx`

- Add a drawer view `'schedules'` and a **Schedules** control button beside Plans. It works like
  the others: `toggleDrawerView`, `aria-pressed`.
- Props: `schedules: Schedules | null` (null shows "Schedules are kept with memory — memory is
  off.", as PlansPanel does), `characterName`, `timeZone`, `notifications: PageNotifications`.
- Read it with `useSyncExternalStore` on `schedules.subscribe` and `snapshot`.
- **Upcoming** (active and paused), one row each, showing:
  - the description;
  - `whenWords` for the next run, or "paused";
  - `repeatWords(…)`, the expression, or "once";
  - "runs on the companion" when it does;
  - the last run, if any: its outcome pill (`ok` / `failed` / `skipped`), summary and when.
- Each upcoming row has buttons: **Pause** or **Resume**, and **Cancel**. Cancel asks for
  confirmation inline: a second press within the row ("Cancel? Yes / No"). No `window.confirm`.
- **Finished** (completed, failed, cancelled) goes in a `<details>` below, collapsed, with the same
  rows and no buttons.
- Header, by permission:

  | Permission | What the header shows |
  |---|---|
  | `default` | a **Let her notify you** button that calls `notifications.request()` |
  | `denied` | the hint "Notifications are blocked for this site in your browser." |
  | `unsupported` | nothing |

- An empty list: "Nothing scheduled. Ask her: \"remind me Thursday at 9 to call the vet\"."
- Style every class in `theme.css` (`schedules-*`) with the teal tokens. No colour literals.
  `theme.test.ts` must pass.
