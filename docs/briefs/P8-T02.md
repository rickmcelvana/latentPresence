## The plan line

> *Provider choice, MariaDB or SQLite choice, browser model consent, mic and camera permissions,
> character choice.* *Done when: no step requires the docs.*

## What main established first (do not re-derive; build on it)

1. **Friends and family will mostly meet this in the Windows desktop app** (P8-T01, D-58), which
   opens on `/`. The same build runs at `app.latentpresence.com` and in `pnpm dev`. Tell them apart
   with `desktopShell() !== null` (`apps/web/src/desktop/desktop.ts`); never sniff the user agent.
2. **Microphone and camera in the desktop app are granted by the shell** (ADR-61, landed in
   `apps/desktop/src-tauri/src/lib.rs`, `permission_for`). WebView2's own prompt named
   "http://tauri.localhost", and a Block there could not be undone. So in the app a
   `getUserMedia` call either succeeds or fails because **Windows** said no (Settings → Privacy &
   security → Microphone/Camera → "Let desktop apps access your microphone/camera"), or there is
   no device. In a browser the browser asks as usual; a refusal is undone from the padlock/site
   icon left of the address bar.
3. **"SQLite" in the plan line is out of date.** `SqliteMemoryStore` is a placeholder that refuses
   everything; the store "on this computer" is IndexedDB, the `memory: 'browser'` setting, and in
   the app it lives in the app's own WebView2 profile. The real choices are the existing
   `MemorySetting`s: `browser` (default — "On this computer"), `companion` (MariaDB through the
   companion), `auto`, `off`. Offer `browser`, `companion` and `off`; leave `auto` to Settings.
4. **How the companion finds MariaDB** (`companion/crates/server/src/bench.rs::database_url`):
   `DATABASE_URL` from the environment, else a `.env` found walking up from the current
   directory. So:
   - **desktop app:** the person sets a Windows **user environment variable** `DATABASE_URL`
     (e.g. `mysql://user:password@host:3306/latentpresence`) and **quits and reopens the app**
     (the companion starts with the app). Steps on screen: Start → search "environment variables"
     → "Edit environment variables for your account" → New… → name `DATABASE_URL`, value the URL.
     There is no in-app field for it (backlog, ADR-61); do not add one.
   - **browser with a checkout:** put `DATABASE_URL=...` in `.env` at the repository root and run
     `pnpm companion` (exact command, in `code`).
   - **hosted app without a companion:** MariaDB is not available; say so and offer "On this
     computer".
   - **"Check"**: `GET {companionUrl}/health`, parsed with `HealthResponseSchema` from
     `@latentpresence/protocol`; `database.connected` true → connected; `database.kind === 'none'`
     → "the companion is running but has no DATABASE_URL"; no answer → "the companion is not
     running" (in the app that cannot happen; say "restart the app"). `chat/chat-memory.ts` has a
     working example (`fetch` with an `AbortController` timeout). In the app the companion URL
     comes from settings already (`withShellCompanion`), and `window.fetch` adds the pairing token
     by itself — just use `fetch`/the settings' `companionUrl`.
     **MariaDB 11.8+ with Vector** is required; say "MariaDB 11.8 or newer".
5. **Model consent** (CLAUDE.md, ADR-09): nothing downloads without `ConsentScreen` (size, licence,
   source). Consent is recorded by `ModelConsent.grant(descriptors)` (`deps.consent` in
   `SettingsDeps`) and checked with `.has(...)` at the moment of use — `/chat` shows its own
   consent only for what is not yet granted. **The wizard records consent; it does not download.**
   Say so: "They download the first time you use them." Descriptors:
   - voice and hearing: `browserModelsFor(settings)` in `apps/web/src/voice/models.ts` (pure,
     imports only descriptors from `@latentpresence/ml-web` — safe to import eagerly; check the
     build does not pull a worker or model into the settings chunk);
   - the character's body: `AVATAR_DESCRIPTOR` in `apps/web/src/call/character-asset.ts`
     (GitHub, VRM Public License — use `ConsentScreen`'s `heading`/`intro`/`agreeLabel` the way
     `CallStage.tsx` does; the default intro wrongly says "Hugging Face");
   - face reading is **not** in the wizard (it is opt-in per call, ADR in P3-T06).
   A server voice/hearing (`tts.kind`/`stt.kind` not the browser ones) needs no browser models —
   `browserModelsFor` already reflects the settings.
6. **API keys:** `KeyField` now saves on blur and Enter (R-56). In the app keys go to Windows
   Credential Manager (`KeychainVault`). **Fix on the way:** `SettingsPanel`'s note "Keys are
   encrypted in this browser's storage…" is false in the app; there say "Keys are kept in Windows
   Credential Manager, not in this app's storage."

## What to build

A production route **`/welcome`** (`WELCOME_PATH` in `App.tsx`, lazy-loaded like `/settings`),
a `WelcomePage`/`Wizard` under `apps/web/src/welcome/`, one step on screen at a time, with Back,
Next and "Skip for now" where a step is optional, and a step indicator ("2 of 6").

**When it shows**
- New settings field `welcomed: boolean` (zod, default `false`) in `settings/settings.ts`. A
  document saved before this field existed and with `llm.modelId !== null` loads as
  `welcomed: true` (people already set up never see the wizard) — do this in the loader, with a
  test; `DEFAULT_SETTINGS.welcomed` is `false`.
- `/` with `welcomed === false` shows the wizard (render it, or `location.replace('/welcome')`);
  with `true`, `/` stays as it is. `/chat`'s unconfigured state links to `/welcome` as well as
  Settings. Settings gets a "Run setup again" link at the top.
- Finishing (or "Skip setup" on the first step) sets `welcomed: true` and goes to `/chat`.
- Save each step's choices as they are made (`saveSettings`), so closing the window halfway
  loses nothing.

**Steps**
1. **Welcome.** Two or three sentences: who she is (a character you talk to, by text or voice,
   with a face); it uses AI models **you** choose and it ships none; nothing leaves this computer
   unless you point it somewhere. "Set up" / "Skip setup".
2. **Language model** (required to talk; may be skipped). Reuse `LanguageModelSection` as it is
   — it already does presets, keys, CORS help and Test connection — with a short lead-in above it:
   "Running Ollama or LM Studio on this computer? Choose it. Otherwise choose a cloud provider and
   paste its key." Next is enabled once a model is chosen; otherwise "Skip for now" (and the Done
   step says she cannot answer until one is chosen, with a link to this step).
3. **Character.** Alice or Theo (reuse `CharacterSection` or its pieces), one line each from the
   persona summaries (`personas/*.persona.json` via what `CharacterSection` already uses). Then the
   **body consent** (`AVATAR_DESCRIPTOR`, "Show the character" / "Not now"); "Not now" is fine —
   `/chat` asks again later.
4. **Memory.** Three choices as cards/radios: On this computer (recommended) / A MariaDB server
   (advanced) / Don't remember. Choosing MariaDB reveals the exact steps for this context (§4) and
   a **Check** button with the result in a `ConnectionStatus`-style pill. Choosing it does not
   require a passing check (they may set it up later), but say what happens until then: "Nothing
   is remembered while the companion has no database."
5. **Voice and hearing.** Explains that talking out loud uses models that run on this computer;
   shows `ConsentScreen` for `browserModelsFor(settings)` with Agree / "Not now (text only)".
   Then **microphone check**: a "Test microphone" button → `getUserMedia({ audio: true })`, show
   "Microphone works" with a small live level for ~3 seconds (an `AnalyserNode`; `deps.createAudioContext`
   exists in `SettingsDeps`), then **stop every track**. On failure, the steps for this context
   (§2): app → Windows privacy settings; browser → the site icon left of the address bar →
   Microphone → Allow, then test again. `NotFoundError` → "No microphone was found." Optional
   **camera check** the same way (`{ video: true }`), a small preview `<video>` for a moment, then
   stopped — say the camera is only used for "Read my face", which is off until turned on.
   Never start the mic or camera without the click.
6. **Done.** A summary of what was chosen (model, character, memory, voice yes/no), anything
   skipped with a link back to it, and "Start talking" → `/chat`.

**Copy rules.** Plain words, no "LLM", "CORS", "IndexedDB", "VRM", "relay" on the main lines (the
existing sections' hints may keep theirs). Every failure says what to do next on screen — that is
the done-when. Desktop vs browser wording only where the steps differ.

## Constraints

- **Do not change** `packages/protocol`, anything under `companion/` or `apps/desktop/`, the vault
  classes, `ModelConsent`, or `LanguageModelSection`'s behaviour (small props for wording are ok).
- Style every new className in `apps/web/src/theme.css` with the existing tokens (ADR-15); no
  colour literals outside `:root`. `theme.test.ts` must stay green. Look at `.settings-section`,
  `.consent-screen`, `.panel`, `.pill-*`, `.btn*` first and reuse them.
- Works at phone width and in the 960×600 minimum window.
- Accessible: each step has a heading that receives focus on step change; buttons are buttons;
  radios are a real `fieldset`/`legend`.
- No new dependencies.
- Tests land with the code (`@testing-library/react`, the `testDeps` pattern in
  `settings/SettingsPanel.test.tsx`; inject `getUserMedia` and the health fetch so no test touches
  a device or the network). At least: the `welcomed` migration both ways; `/` routes to the
  wizard only when not welcomed; the step order and Back/Next/Skip; Next disabled on the model
  step until a model is chosen; consent recorded on Agree and **not** on Not now, and nothing
  fetched either way; the memory Check's three outcomes; a mic refusal shows the desktop steps in
  the app and the browser steps in a browser (stub `desktopShell` via `initDesktop` with a fake
  `__TAURI__`, as `desktop.test.ts` does, and reset after); tracks are stopped after a test;
  finishing sets `welcomed` and lands on `/chat`; the vault note in the app.
- `pnpm gate` green before you stop. **Do not commit.** Report: files changed, test count, and
  anything you were unsure of.

## Outcome

A Sonnet subagent built the wizard from this brief in one pass, gate green. Its own calls, all
kept: `/` renders the wizard in place (no redirect); `isWelcomed` in `settings/welcomed.ts`
repeats the migration rule so `App.tsx` does not pull `settings.ts` (~220 kB) into the entry chunk
(`welcomed.test.ts` checks they agree); its own injectable level meter, since
`MinimalAudioContext` has no analyser; a fourth Check outcome (a `DATABASE_URL` that does not
connect); the voice step's Next waits for Agree or Not now.

Main's review: walked it in the dev server at 960×600 and phone width — Ollama tested to 24
models and one chosen, Alice with the body declined, MariaDB's steps and a Check against no
companion, voice consent (482.9 MB listed, nothing fetched), the summary, Start talking → `/chat`
with `welcomed: true`. In the release app with a fresh profile: the wizard opens at `/`, and the
keys note says Credential Manager. One copy fix (the welcome line called the app "a character").
**Not exercised by main:** the microphone and camera tests on a real device (jsdom only; the
shell's grant was checked separately), the MariaDB steps against a real database in the app.
