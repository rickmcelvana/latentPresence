# P8-T06 — The companion's own settings, in the app

- **lane:** main (the companion, the shell, the bridge, the Test message — landed in a299032 and
  the reload command after it), sub (the Settings UI and the wizard step — this brief)
- **status:** briefed 2026-10-17
- **why:** Rick, after R-57: Home Assistant, the notes folder (Files), the manuals folder
  (documents), web search and his databases all live in `mcp.json` / `documents.json` under
  `%APPDATA%\latentPresence`, edited by hand. Without those files a new person has none of it, and
  nothing in the app says so. Adding Home Assistant under Tools → "Add a server" read as "not up"
  (it was up and refused the page — fixed in main's half).

## What main built (use it; do not change it)

**`apps/web/src/desktop/companion-config.ts`** — the whole contract. Read its doc comment first.
`companionConfigApi(invoke)` gives `read`, `change`, `pickFolder('files' | 'documents')`,
`pickSqlite(name)`, `openFile`, `reload`. Every call that changes something restarts the
companion and resolves with the new `CompanionConfig`; a refused change **rejects with a sentence
meant for the person** (e.g. `Home Assistant: "homeassistant.local" is not an http(s) address,
like http://homeassistant.local:8123`) — show it as it is. `pickFolder` / `pickSqlite` resolve
`null` when the person cancels the system dialog.

Facts the UI must respect:
- **No secret comes back.** A token, key or database address is a `SecretState`:
  `'stored'` (in Windows Credential Manager), `'inFile'` (written in `mcp.json` in plain text —
  saving that section moves it to Credential Manager), `'missing'`. Treat a secret field like
  `settings/KeyField.tsx` treats a key: a password input when there is none or when replacing,
  otherwise a pill and Replace. **Omitting `token` / `key` in a change keeps the saved one.**
- **The page cannot add a folder by name.** There is no such change. "Add a folder…" calls
  `pickFolder`, which opens Windows' own folder dialog; the person picks. Removing is a change.
- **Programs (`servers`) are read-only.** List them (name, `summary`, "off" when `disabled`) with
  "Open mcp.json" (`openFile`) and, after a hand edit, "Reload" (`reload`). Say why: they start
  programs on this computer, so they are changed only in the file.
- `problems` non-empty: a file does not parse. Show the sentence(s) at the top with Open mcp.json
  and Reload; the sections then show empty.
- Every change restarts the companion, so her tools from it drop for a few seconds. After a Home
  Assistant change, show its state by asking the companion's tool list until Home Assistant is no
  longer `starting` (the shape: `GET {companionUrl}/mcp/tools` → `{ servers: [{ id: 'homeassistant',
  state: 'ready' | 'starting' | 'failed', detail }] }`; there is a client in
  `packages/providers/src/mcp/companion.ts` and `connectCompanionTools` in `chat/chat-tools.ts` —
  use one of those, through `deps.fetch`/`window.fetch`, which already carries the pairing token in
  the app). `ready` → "Connected"; `failed` → its `detail`.
- **Turn the matching switch on.** Adding Home Assistant, a Files folder, web search or a database
  is pointless while Settings → Tools → "Offer the companion's tools" (`settings.tools.companion`)
  is off; adding a documents folder likewise needs `settings.documents.search`. When a change adds
  one of those, set the switch to true (through the settings the parent owns), and say so in one
  line. Never turn one off.
- Desktop only. Decide with `desktopShell() !== null` (`desktop/desktop.ts`); in a browser none of
  this renders (the browser's companion is the person's own process, ADR-63).

## What to build

### 1. `settings/CompanionSettings.tsx` — Settings, in the app

Rendered by `SettingsPanel` in the app only, after the Tools section, as its own panels (one per
topic, each `.panel settings-section`) under a heading such as "On this computer". Take an
injectable `api?: CompanionConfigApi` (tests pass a fake; production builds it from the shell).
Load with `read()` on mount; "Looking…" until then; an error → its sentence and a Retry.

- **Home Assistant.** Address (text) and token (secret). Save → `{ kind: 'home', url, token? }`.
  Remove → `removeHome`. A hint that says where a token comes from: "In Home Assistant: your
  profile → Security → Long-lived access tokens → Create token" and that the address is like
  `http://homeassistant.local:8123`. Show `problem` when present. After a save, the state as above.
  One line: her devices' permissions are under Tools → List (they start as "Ask first").
- **Folders she may read** (`roots`): each with Remove (`removeRoot`), and "Add a folder…"
  (`pickFolder('files')`). One line: she can only read, never change, what is in them.
- **Documents she can search** (`folders`): each with Remove (`removeDocumentsFolder`), and "Add a
  folder…" (`pickFolder('documents')`). Then the embedding model: base URL, model, dimensions,
  document and query prefixes, Save (`{ kind: 'embedding', embedding }`) and Remove
  (`embedding: null` — "keyword search only"). A one-click **"Use Ollama's nomic-embed-text"** that
  fills `http://127.0.0.1:11434/v1`, `nomic-embed-text`, `768`, `search_document: `,
  `search_query: ` (what Rick's file has; it is the documented setup) for them to Save.
- **Web search** (`web`): provider (None / SearXNG / Tavily / Brave), SearXNG's address or the
  provider's key (secret), "She may also read web pages" (`readPages`). Save → `web`; Remove →
  `removeWeb`. Show `problem`.
- **Databases she may query** (`databases`, read-only for her): each row: name, description, the
  address (already without its password) or the SQLite path, the secret state, `problem`, Remove.
  Add: name (letters, digits, `-`, `_`), address (`postgres://`, `mysql://`, `mariadb://`, a
  password input), description → `addDatabase`; or "Add a SQLite file…" with the name →
  `pickSqlite(name)`.
- **Programs** (read-only, as above).

Every action: buttons disabled while one is in flight; on success the view is replaced by the
result; on rejection the sentence shows next to the section that caused it. A one-line note
somewhere visible: "Changes restart the companion; her tools from it are back in a few seconds."

### 2. A wizard step — "Your home, notes and documents" (app only)

In `welcome/Wizard.tsx`, between Memory and Voice, **only in the app** (the step count becomes 7
there; a browser keeps 6 — make the indicator and Back/Next follow the real list). Optional:
"Skip for now". Reuse the Home Assistant, Folders and Documents pieces from `CompanionSettings`
(export them, or a compact mode) — **not** web search, databases or programs (Settings has them).
For documents, offer the Ollama embedding button only as a suggestion. The summary step lists
what was connected and links back to this step for anything skipped. Turning the switches on (see
above) matters most here.

### 3. Small things

- `settings/ToolsSection.tsx` "From the companion" text: in the app, point to the new section
  ("Set them up under On this computer, below") instead of to editing mcp.json.
